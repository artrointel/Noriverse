# 개발 로드맵

2026년 11월 20일 기준. Phase 1에 착수했다. Phaser 오목과 충돌 장면, React의 화면·설정 관리, 로컬 Durable Object 방 서비스와 WebRTC 착수 동기화를 첫 프로토타입에 구현했다. 실제 Cloudflare 환경, TURN 중계와 모바일 실기기 매트릭스는 후속 검증 대상이다. 엔진과 인프라의 채택은 실측 후 결정한다.

첫 로컬 검증에서 Chrome 두 세션으로 방 참여, 양쪽 착수 동기화, DataChannel 종료 후 동일 보드 복구, 재경기를 확인했다. 테스트의 WebRTC 환경에서는 Chrome의 mDNS 후보 기능을 끈 상태에서 직접 연결에 성공했다. 기본 브라우저 설정, 실기기, 서로 다른 네트워크에서의 연결 성공률과 P95는 별도 측정한다.

WebRTC 직접 연결이 실패하거나 7초 안에 준비되지 않으면 해당 참가자만 방 WebSocket으로 경기 데이터를 중계한다. 호스트의 판정과 스냅샷으로 경기를 이어가며, 연속으로 발생하는 터치 위치 효과는 직접 연결에서만 전달한다. 공개 반영에는 Worker와 웹 양쪽 배포가 필요하다.

사용자가 Chrome 두 창에서 로컬 프로토타입 동작을 확인했다. 이후 홈, 게임 라이브러리와 상세, 설정, 대기실, 경기·결과 화면을 연결했다. 오목의 로컬·친구 대전과 알까기 연습에 같은 설정·경기 화면 구조를 적용했다. 첫 방문에서 브라우저 언어 목록과 시스템 테마를 사용하며, 수동 설정은 브라우저에 저장한다.

오목·알까기에 목재 바둑판과 흑백 돌 이미지, 그림자와 물리 연출을 적용했다. 알까기는 연습과 함께 한 기기 2인 대전을 제공한다. 각자 다섯 돌을 들고 흑부터 한 번씩 튕기며, 돌의 중심이 판을 벗어나면 제거된다. 한쪽이 전멸하면 상대가 이기며 같은 샷에 양쪽이 전멸하면 무승부다. 한국기원 자료와 공개 게임의 조작·장외 규칙을 참고했다. [한국기원](https://m.baduk.or.kr/news/B02_view.asp?news_sum_no=18) · [다섯 돌 규칙](https://playfulo.com/ko/games/alkkagi) · [장외 판정](https://www.board-pan.com/guide-alkkagi.html)

배경음과 공용 UI·게임 효과음은 Web Audio 합성을 사용한다. 개인 설정은 언어, 테마, 사운드로 나뉘며 배경음과 효과음의 크기는 각각 저장한다. 오델로를 추가해 기존 오목 방의 착수 동기화, 기권과 재경기를 공유하도록 했다. 오델로는 돌을 뒤집을 수 있는 위치만 허용하고, 둘 곳이 없으면 패스하며, 양쪽 모두 둘 곳이 없을 때 점수를 확정한다. [오델로 공식 규칙](https://worldothello.org/about/about-othello/othello-rules/official-rules/english)

두 게임과 연습 종료에 마지막 장면을 유지하는 공통 결과 화면을 연결했다. 이름을 등록한 사용자는 익명 세션 쿠키로 프로필을 사용한다. 종료와 기권 기록은 프로필별 Durable Object에 경기 ID로 중복 없이 저장한다. 기존 게임 기록의 시간도 합산하며 1레벨에서 시작해 3,600초마다 레벨이 오른다. 공유 링크에서 누적 시간, 게임별 합계와 각 게임의 최근 기록 20개를 조회한다. 전적은 브라우저가 제출한다. 오목은 방마다 3–3 허용 또는 흑 착수 금지를 선택할 수 있다. 판정은 한 수에서 열린 삼을 만드는 두 방향을 확인하며 5목 승리가 우선한다. 첫 방문 시 프로필이 없으면 기존 이름 입력 화면을 팝업으로 열고, **나중에**를 누르면 현재 방문 동안 건너뛸 수 있다. 프로필 API를 연결하기 전의 GitHub Pages에서는 표시 이름을 브라우저 쿠키에 저장한다.

각 게임의 플레이 방식은 **방 만들기**와 **혼자하기**로 통일했다. 오목과 오델로는 친구 방을 지원하고, 알까기는 한 기기에서 순서대로 양쪽을 조작한다. 게임 진행 정보에는 경기 시작 시각 기준으로 초 단위 플레이 시간을 표시한다.

상단 내비게이션의 **방 만들기**에서 게임을 고르면 해당 게임의 온라인 설정 화면으로 이동한다. 방제는 프로필 이름을 넣은 다섯 문구 중 하나로 시작하고, 주사위나 직접 입력으로 바꿀 수 있다. 방 만들기를 누르면 방 코드를 발급하고 설정한 방제를 대기실과 경기 중 랭킹 팝업에 표시한다.

턴제 재경기에서는 직전 경기의 패자가 선공 색을 받는다. 체스는 백, 오목·오델로·알까기는 흑이 먼저 두며 기권과 시간 초과 패배도 반영한다. 무승부는 색을 유지한다.

오목의 6목 설정은 3–3과 별도로 선택한다. 기본값은 국제 오목 규칙에 따라 정확히 5목만 승리이며, 6목 이상도 승리로 인정하도록 바꿀 수 있다. 방의 설정은 양쪽과 재경기에 유지된다. 모바일 오목·오델로·체스에서는 같은 위치를 빠르게 두 번 탭해 착수를 확정한다. [국제 오목 규칙](https://gomoku.renju.net/gomokurules/)

게임 설정에서 턴 제한시간을 선택한다. 마지막 3초는 효과음으로 안내한다. 시간이 다 되면 상대가 승리를 확정하거나 같은 턴에 15초를 추가할 수 있다. 친구 방은 호스트가 시계와 선택 권한을 판정하며, 알까기는 돌이 움직이는 동안 시계를 멈춘다. 그래픽의 안티에일리어싱은 기본으로 켜져 있고 다음 경기부터 적용된다. 친구는 공개 프로필 링크 또는 대기실에서 개인 목록에 저장할 수 있고, 대기실은 접속 중인 참가자의 공개 프로필 요약만 표시한다.

체스는 한 기기와 온라인 대전, 공통 턴 제한시간과 전적을 지원한다. 합법 수와 결과는 chess.js로 검증한다. 놀이버스에서는 3회 반복과 50수 규칙을 자동 무승부로 적용한다. 원목 보드와 체스 기물의 텍스처를 사용하고, 기물 이동은 선형으로 보간하며 잡힌 기물은 기울어지며 사라진다.

체스는 선택한 기물의 이미지 실루엣에 아웃라인을 입히고, 이동할 수 있는 빈 칸과 잡을 수 있는 칸을 서로 다른 모양으로 표시한다. 최근 수와 포커스 표시는 오목·오델로에서도 같은 Phaser 렌더링을 사용하며, 알까기의 조준 표시에도 같은 테두리 스타일을 적용한다. 모션 줄이기 설정에서는 표시가 즉시 나타난다.

알까기 온라인 방에는 최대 4명이 참가할 수 있다. 호스트는 각 참가자에게 WebRTC로 발사와 확정 배치를 전달하고 각 브라우저는 물리를 계산한다. 호스트가 확정한 위치, 장외 상태, 다음 차례와 승패를 참가자들이 공유한다. 도중에 다시 연결하면 마지막 확정 배치와 진행 중인 발사를 받아 복구한다. 기본 시작 돌은 한 사람당 5개로 3~7개까지 바꿀 수 있고, 바둑판 크기와 고정·랜덤 배치도 선택할 수 있다. 3~4인 개인전에서는 돌을 모두 잃거나 시간 초과로 탈락하며 최후 생존자가 이긴다. 재경기는 첫 탈락자부터 시작한다.

턴 시간은 프리셋 외에 1~3600초를 직접 입력할 수 있고 기본값은 제한 없음이다. 경기 진행 버튼에는 현재 턴과 카운트다운을 표시한다. 개인 설정의 접힌 언어와 테마에서 현재 값을 확인하고, 사운드는 볼륨을 유지한 채 한 번에 음소거할 수 있다. 터치 좌표는 경기 채널에서 정규화해 상대에게 전달하며, 프로필의 효과 선택과 현재 기기의 표시 토글을 제공한다.

친구 초대는 호스트의 방 자리와 친구 목록을 검증하고, 프로필의 WebSocket으로 접속 중인 화면에 전달한다. 접속을 유지하는 브라우저를 온라인으로 표시하며 친구 목록은 15초마다 갱신한다. 오프라인 친구는 접속 후에도 유효 시간 안에 초대를 받을 수 있다. 초대는 최대 3분간 유지된다.

친구는 상대가 요청을 수락하면 양쪽 목록에 등록된다. 대기실에서는 보낸 사람의 이름으로 새 요청을 하단에 알리고, 같은 방 참가자의 요청은 참가자 목록에서 바로 수락할 수 있다. 미처리 요청은 프로필의 친구 관리에서 수락하거나 거절할 수 있다. 기존에 서로 추가한 친구는 유지한다. 온라인 상태와 현재 방은 접속 이벤트로 갱신하며, 비정상 단절 시에는 신호가 만료되면 오프라인으로 전환한다. 참가 화면은 서버가 입장 가능을 확인한 최근 방을 보여준다. 친구 목록에서는 친구가 접속 중인 방에 남은 자리나 이전에 예약된 자신의 자리가 있을 때 참가할 수 있다. 알까기 돌 선택에 공용 밝기 애니메이션을 적용했으며, 온라인 결과 화면에서 참가자가 방장에게 재경기를 요청할 수 있다.

친구 관계는 어느 쪽에서든 삭제하면 두 목록에서 해제된다. 사천성은 최대 두 번 꺾이는 가로·세로 경로로 타일을 연결하는 퍼즐이다. 한 판에는 선택한 콘셉트의 Phaser 아틀라스와 전용 보드 배경을 적용한다. 초기 클래식 아틀라스를 제거해 현재 일곱 콘셉트를 지원하며 기본 선택은 랜덤이다. [KShisen 규칙](https://docs.kde.org/trunk_kf6/en/kshisen/kshisen/howto.html)

사천성 격자는 6×6, 8×8, 10×10, 12×12 중 고르며 권장 제한 시간은 각각 30초, 1분, 1분 45초, 2분 45초다. 타일 밀도는 기본 60%이고 30~100% 또는 랜덤으로 설정할 수 있다. 장애물 밀도의 기본값은 전체 칸의 20%이며, 0%를 선택하면 장애물이 없다. 짝수 개의 타일을 먼저 배정한 뒤 남는 공간까지만 장애물을 배치한다. 랜덤 밀도는 추첨한 타일 밀도에 이 상한을 적용한다. 장애물은 섞기에도 자리를 유지한다. 1초 안에 연속으로 짝을 제거하면 콤보가 올라간다.

방장은 게임 변경 팝업에서 현재 인원으로 플레이할 수 있는 게임을 라이브러리 카드로 고른다. 프로필은 경기 기록이 있는 게임만 표시한다. 저장에 실패한 경기 결과는 해당 프로필의 브라우저에 보관하고 프로필을 열거나 네트워크가 복구되면 재전송한다. 앱의 뒤로가기 링크는 브라우저의 이전 화면을 따르고, 주소로 직접 열었을 때는 화면별 기본 경로를 사용한다.

사천성 2~4인 방에서 대전과 협동을 고를 수 있다. 참가자 전원이 준비되면 공통 제한시간이 시작된다. 대전은 같은 배치의 보드를 각자 풀며 먼저 클리어한 사람이 이긴다. 협동은 보드를 공유하며 함께 클리어하면 전원이 이긴다. 시간이 끝날 때까지 클리어하지 못하면 전원이 패배한다. 힌트와 섞기는 기본 3회이며 0~5회까지 설정할 수 있다. 대전에서는 각자 횟수를 쓰고 협동에서는 공유한다. 섞기는 연결 가능한 짝이 남아 있을 때도 사용할 수 있다. 진행 중 처음 입장한 참가자는 대기실에서 다음 경기를 기다린다.

사천성 장애물 터치에는 0.5초의 흔들림과 두 번의 적색 점멸을, 타일 선택에는 노란 표시와 종이 효과음을 적용한다. 제거 연출은 테마별 입자와 타일 모션을 사용하며 콤보에 따라 입자 수, 연결선 광량과 지속 시간이 증가한다. 콤보 숫자와 `Combo!`는 한 장의 생성 이미지 아틀라스에서 조합한다. 모션 줄이기에서는 콤보 배너를 이동 없이 표시한다. 보드 아래 Phaser HUD는 하나의 공용 텍스처로 패널, 상태 아이콘, 섞기·힌트 버튼을 그리며, 각 테마에는 전용 카드 배경을 적용한다.

사천성 온라인 대전은 감정 표현 옆에 상대별 타일 제거 진행률을 표시한다. 상대 콤보는 기존 경기 상태를 통해 전달되며, 내 콤보보다 작고 고음이 줄어든 소리와 짧은 메아리로 들린다.

개인 설정의 접속 상태를 오프라인으로 바꾸면 서버 프로필에 기록된다. 수동으로 온라인으로 돌아올 때까지 친구 목록의 방 공개와 게임 초대를 중지한다. 경기 정보는 방 참가자의 프로필과 담당 색을 표시한다. 각 게임의 경기 화면 바깥쪽에는 테마에 맞춰 약하게 처리한 기존 게임 이미지를 표시한다.

내 프로필에서도 공개 접속 상태를 바꾼다. 친구 목록의 마지막 접속 시각은 공개 온라인 연결이 시작되거나 온라인으로 직접 전환할 때만 갱신하며, 숨김 상태로 접속해도 이전 공개 시각을 유지한다.

프로필의 친구 관리 버튼에 공개 온라인 인원과 전체 친구 수를 표시한다. 프로필은 방 조회를 건너뛰고 공개 접속 상태를 집계한다. 친구 목록과 초대 팝업에서는 참가 가능 방 정보도 조회한다.

캐치마인드는 혼자 연습과 2~4인 친구 방을 지원한다. 방장은 한국어·영어 제시어, 1·2·3분 맞히기 시간, 인당 출제 횟수, 힌트 간격(기본 30초), 다섯 그림 맵 또는 랜덤을 정한다. GO 뒤 출제자에게만 제시어를 2초 보여주고 제한시간을 시작한다. 글자 수, 분류, 제시어에 따라 색상 힌트를 순차 공개한다. 첫 정답자는 남은 시간에 따라 100~300점을 얻고 다음 출제 우선권을 갖는다. 출제권이 없거나 아무도 못 맞히면 출제권이 남은 사람 중 점수 상위자가 이어서 그린다. 동점은 누적 정답 시간이 짧은 순과 경기 시작 시 추첨한 순서로 가려 한 명만 승리한다. 펜·붓·분필·마커와 자유 굵기, 최근 사용 색, 획 단위 실행 취소·재실행을 지원한다. 그리기 입력은 묶어서 전송하고 재접속하면 그림과 점수를 복원한다.

캐치마인드는 그림 위에 시계와 제시어 배지를 표시하고, 아래의 투명한 Phaser HUD에 도구별 카툰 아이콘과 Jua 글꼴, 힌트와 점수를 배치한다. 정답 공개 전까지 맞히는 사람에게 제시어를 숨긴다. 테두리까지 그릴 수 있으며, 붓은 포인터 속도에 따라 굵기가 변한다. 지우개는 잉크만 지운다. 그리기 입력 취소 후에도 새 획을 시작할 수 있으며, 긴 그림의 복구 스냅샷은 방 중계 크기 안에 들어가도록 압축한다.

공통 경기 화면은 게임 정보와 전체화면 사이의 물음표 버튼에서 게임별 조작 도움말을 연다.

라이브러리는 전체·즐겨찾기 범위를 유지하면서 시작 가능한 인원과 전략·액션 태그를 검색과 함께 필터링한다.

라이어 게임은 3~4인 친구 방에서 비공개 역할 카드, 순서대로 힌트 제출, 비밀 투표를 지원한다. 최다 득표가 동률이거나 라이어를 지목하지 못하면 라이어가 이긴다. 라이어를 지목하면 한 번의 제시어 추측 기회를 주고, 틀리거나 제한시간이 지나면 시민이 이긴다. 역할과 투표 내용은 호스트가 관리하며 참가자별로 자기 카드와 투표만 전송한다.

라이어 게임 전용 Phaser HUD에 단계, 타이머, 비공개 카드와 방 내 라이어 누적 점수를 표시한다. 개발 환경의 대기실에서 방장은 비어 있는 자리에 입력 없는 테스트용 목업을 추가하거나 제거할 수 있다.

대기실과 경기 화면에서 방 랭킹보드를 열고 경기별 내역과 획득 점수를 조회할 수 있다. 상위 세 자리는 금·은·동 메달로 구분한다. 기존 순위에서 앞지른 참가자가 생기면 경기 화면의 랭킹 버튼 옆에 대표 변동을 3초 동안 표시한다. 게임을 바꿔도 같은 방에서 지급한 점수를 유지한다. 점수와 동점 기준은 [방 랭킹보드 점수](room-ranking.md)에 기록한다.

대기실 상단 게임 카드 오른쪽 아래에 게임 설정, 방 게임 변경, 게임 시작, 방 나가기를 순서대로 배치한다. 목업 추가·제거는 참가자 목록에서 한다. 목업 경기의 점수는 대기실과 경기 화면의 테스트 랭킹보드에서 확인할 수 있다.

공개 프로필과 내 프로필의 경험치 아래에 뱃지를 표시한다. 전체 뱃지 팝업은 획득과 미획득 탭을 제공하고, 미획득 이미지는 흑백으로 표시한다. 뱃지 이름·업적 설명·달성 기준은 [공용 명세](../packages/protocol/badges.ts)에 둔다. 게임 정복은 기존 온라인 전적에도 적용하며, 방 연승·역전·랭킹은 새로 완료한 실제 다인 경기부터 집계한다. 연승과 연패는 한 방에서 각자 참가한 경기 순서로 계산하며 무승부에서 끊긴다. 랭커는 실제 다인 경기 기록이 있는 방이 종료될 때 랭킹보드와 같은 기준으로 1명을 선정한다. 비공개 프로필 알림 연결은 새 뱃지와 획득일도 전달한다.

프로필 편집에서 투명 캐릭터 15종과 투명 또는 단색 배경을 미리 보고 저장할 수 있다. 15종 중 5종은 픽셀 아트다. 공개 프로필과 방 참가자 목록은 저장한 배경색을 적용하며, 이모지 말풍선은 캐릭터 레이어만 렌더링한다. 이모지 목록은 전용 효과음이 있는 항목을 재생 배지로 표시한다.

공개 Pages와 Worker는 새 프로필 선택지를 지원하는 버전으로 함께 갱신한다. 내 프로필에서 삭제를 확인하면 공개 프로필, 전적, 친구 관계와 대기 중인 친구 요청을 삭제하고 브라우저 세션을 만료시킨다. 프로필 서버를 연결하지 않은 배포에서는 브라우저 쿠키의 프로필과 터치 설정을 지운다.

배경음은 총 26곡으로, 홈·로비에서 고르는 24곡과 경기 전용 2곡이 있다. 사운드 설정은 곡 이름 아래에 분위기 태그를 표시하며, 곡 이름을 누르면 다른 곡을 무작위로 선택한다. 경기에서는 게임별 후보를 사용하고, 새 경기 ID로 재경기가 시작되면 직전 곡을 제외하고 고른다.

모든 경기 화면의 우측 하단에 감정 표현을 제공한다. 반투명 팝업의 탭은 최근, 기본, 이모지 순이다. 이모지 탭에서 한글·영문 이름이나 관련어로 검색한 이모지를 추가할 수 있다. 최근 이모지 최대 5개와 추가한 이모지는 브라우저 쿠키에 저장한다. 방장은 경기 시작 시 참가자 순서대로 네 모서리에 고정 슬롯을 배정한다. 4인을 초과하면 같은 순서로 슬롯을 돌려 쓰고, 같은 슬롯의 이전 표현은 최신 표현으로 교체한다. 말풍선은 3초간 표시하며 등장할 때 두 번 커지고, 기본 이모지 17개는 참가자 각자의 효과음 설정에 따라 전용 효과음이 함께 난다. 찰싹은 110ms 간격으로 두 번 재생한다. 기본 탭의 이미지는 후속 작업이다.

턴제 게임과 사천성은 경기 화면의 지연 로딩, 플레이 시간 표시와 초 단위 카운트다운을 공유한다. 방 상태 초기화와 재연결 표시 조건은 방 모델에서 관리한다.

모든 게임은 Phaser 보드 위 공용 안내 레이어에 공용 아틀라스와 합성 효과음으로 3·2·1·GO를 표시한다. 온라인은 참가자의 화면이 준비되면 호스트가 공통 시작 시각을 정한다. 입력과 경기 시간은 GO가 끝난 뒤 시작한다. 경기가 끝나면 안내가 1.5초간 표시되고 0.5초 뒤 결과가 열린다. 상태 초기화 중에도 전체화면 컨테이너를 유지한다. 연습 모드는 종료 버튼을 제공한다. 프로필 플레이 시간·전적·레벨에는 온라인 경기만 집계하며, 이전 연습 기록도 집계와 최근 경기 목록에서 제외한다. 대기실 이모지는 브라우저 화면 네 모서리에 고정되며 경기 종료 뒤에도 이모지를 보낼 수 있다. 알까기 세 보드 옵션의 물리 판정 한 변은 각각 30% 늘렸다.

시작·종료 안내는 투명 픽셀 아트 아틀라스에서 숫자와 한글·영문 결과 이미지를 골라 보드 위에 표시한다. 인게임 조작 버튼은 공용 스타일을 사용하며 결과 보기에는 강조 스타일을 유지한다. 상단 정보는 사천성의 실제 모드·테마·격자 크기와 알까기의 경기장 프리셋처럼 판마다 의미가 달라지는 정보를 표시한다.

프로필 터치 효과는 은은한 파티클, 물결, 꽃잎 회오리, 픽셀 반딧불, 픽셀 폭발과 끄기를 지원한다. 선택한 항목의 오른쪽에서 표본을 반복 재생하고, 경기 중 직접 연결된 참가자는 터치 좌표와 선택한 효과를 함께 전달한다. 미리보기와 경기 모두 재생마다 각 입자의 방향, 거리, 속도와 크기를 바꾼다. 픽셀 효과는 사각 실루엣을 유지하면서 위치와 투명도를 연속 보간한다. 다섯 효과는 픽셀 폭발의 기존 크기에서 20% 줄인 표시 범위를 공통 기준으로 삼는다.

오목과 체스는 마우스와 터치의 첫 목적지 입력에 반투명 기물을 표시하고, 같은 자리를 한 번 더 선택하면 착수한다. 두 게임의 도우미 표시는 녹색 계열을 사용한다. 온라인 체스의 상대 턴에는 상대 기물을 선택해 합법적인 목적지를 회색으로 볼 수 있다.

저장소 리팩토링에서 게임 ID와 방 정원을 공용 프로토콜에 모았다. 공통 경기 화면은 입장한 게임의 Phaser 씬을 따로 로딩하고, 오목·오델로·체스는 터치와 마우스 좌표를 수로 바꾸는 입력 모듈을 공유한다. 로컬 경기 상태 전이, 온라인 경기 스냅샷 검증, 프로필 상태 관리를 화면에서 분리했다. 방 HTTP 라우터와 Durable Object 구현을 분리했으며 워커 바인딩, 기존 방 메시지 형식과 저장 구조는 유지했다.

게임 설정 페이지와 대기실의 방장용 설정 팝업은 섹션으로 나뉜 같은 규칙 편집기를 사용한다. 사천성은 고정 밀도에서 타일, 장애물, 빈 칸의 개수를 즉시 보여 준다. 사천성 보드는 외곽 색상을 고정하고 브라우저의 자동 어둡게 처리를 피하도록 설정한다. 대기실 상단의 게임 카드에는 현재 규칙과 대기실 감정 표현을 표시하며, 방장의 경기 시작 버튼은 참가자의 연결을 기다린다. 대기실 배경과 참가자별 공개 전적은 선택한 게임을 따른다. 완료된 경기의 결과와 플레이 시간은 방 안에서 누적되고, 새로 참가하거나 재접속한 플레이어에게도 표시된다. 방이 닫히면 경기 기록은 사라진다.

손님은 사용하던 브라우저에서 방 코드를 다시 입력하면 호스트가 보관한 경기 상태를 이어받는다. 방 코드와 함께 브라우저에 보관한 손님 자리 토큰으로 재접속을 확인하고, 호스트의 방 연결이 종료되면 방을 닫는다. 체스 승격 선택창은 보드 안에 표시하며 퀸, 룩, 비숍, 나이트 중 하나를 고를 수 있다.

손님이 진행 중인 경기에서 끊기면 같은 브라우저의 홈에서 버튼 한 번으로 재입장한다. 방장은 현재 인원이 들어갈 수 있는 게임으로 대기실의 게임을 바꿀 수 있다. 방 코드와 참가자는 유지하고 경기만 초기화하며, 중간에 바꾼 경기는 전적에 기록하지 않는다. 온라인 경기에는 내 차례 표시와 강화된 알림음을 제공한다. 체스 게임 정보에는 흑백별로 잡힌 기물을 집계하고, 선택한 기물에는 공용 아웃라인과 밝기 애니메이션을 적용한다.

경기 중 설정에서 안티에일리어싱과 렌더링 해상도를 조절한다. 자동 해상도는 고정 내비게이션 아래에서 경기 카드 내부의 툴바·하단 조작 영역·여백과 캔버스만 맞춘다. 카드 바깥의 페이지 제목과 여백은 공간 예산에 포함하지 않으며, 첫 로딩이 끝나면 카드를 표시 영역 중앙으로 스크롤한다. 캔버스 렌더링은 표시 크기와 기기의 픽셀 밀도를 반영하며, 가로 상한은 자동 1920px 또는 수동 선택값이다. 사천성은 HUD를 포함한 화면 비율을 유지한다. 설정에서는 렌더링 해상도와 필요시 CSS 표시 크기를 각각 보여 준다. 크기를 바꿔도 게임의 논리 좌표와 진행 상태는 유지된다.

일반 경기 화면의 외곽은 보드와 조작 영역 크기에 맞춰 투명하게 표시한다. 결과 팝업은 공용 블러와 테마별 밝기 오버레이를 적용하며, 팝업 가장자리 밖에서도 마지막 보드 상태를 확인할 수 있다.

## MVP 제안

공개 MVP는 **두 사람이 방 하나에서 오목과 알까기를 오가며 플레이**하는 범위를 권한다. 둘 다 익숙한 규칙이고, 턴제 상태와 물리 상태의 차이로 공통 계층을 검증할 수 있다. 내부 테스트는 오목 한 종으로 시작하고, 알까기는 물리와 입력 최소 기능부터 구현한다. 출시 일정이나 검증 결과에 따라 한 종만 공개하고 두 번째 게임은 내부 검증에 쓰는 대안도 있다. 그 경우 게임 전환에 대한 사용자 가설은 두 번째 게임 공개 뒤 확인한다.

- 게임 라이브러리와 상세·규칙, 익명 닉네임, 1:1 사설 방, 링크 또는 코드 참가, 최소 대기 로비, 플레이, 결과, 재경기, 같은 방의 게임 전환
- 신뢰성 있는 턴제 동기화와 호스트 물리 상태 전달, TURN, 단기 재접속과 스냅샷 복구, 호스트 이탈 안내
- 한국어·영어, 라이트·다크·시스템 테마, PC와 모바일 입력, 양방향 레이아웃 및 페이지 내 확장과 지원되는 환경의 네이티브 최대화면
- 기본 접근성, 오류 원인 안내, 운영용 연결·비용 지표

싱글플레이와 AI, 공개방·계정·순위표, 채팅, 큰 파티·팀, 비공개 정보 게임, 장기 세션 저장과 호스트 이전은 초기 공개 범위에서 제외한다. 추후 수용을 위해 구조적 경계만 확보한다.

## Phase 1 검증 범위와 기준

Phaser 4.2.1과 Cloudflare 방 인프라·STUN/TURN을 첫 후보로 검증한다. 오목 보드로 방 참가·착수·상태 복구를, 작은 원형 충돌 장면으로 물리·렌더링·터치 입력을 검증한다. 아래 수치는 합의한 초기 목표이며 표본 수와 기기·네트워크별 결과를 함께 기록한다.

| 검증 | 방법과 초기 목표 |
| --- | --- |
| 초대 및 P2P | PC Chrome·Edge·Firefox와 macOS Safari, iPhone Safari, Android Chrome 중 실제 접속 쌍을 정한다. 동일 Wi-Fi, Wi-Fi ↔ LTE/5G, 상이한 인터넷 회선 및 가능하면 제한망, 강제 TURN/TLS를 포함한다. 여러 네트워크에서 적어도 60회 유효 방 참가를 시도해 성공률 목표는 95% 이상, 사용자가 참가를 누른 뒤 플레이 가능까지 P95 8초 이내다. 네트워크·기기별 표본 수와 직접·중계를 별도 보고한다. |
| 신호와 복구 | 정상·만료·정원 초과·버전 불일치, 손님 백그라운드/네트워크 전환, 호스트 백그라운드/종료, 중복 입력과 연결 재시도를 검증한다. 단절 전후 마지막 확정 상태가 일치하고, 호스트 장기 이탈은 유예 후 중단 처리되어야 한다. |
| 엔진 통합 | 같은 크기·리소스의 장면에서 Phaser 4.2.1을 우선 측정해 필요 시 3.90 또는 Excalibur와 비교한다. 초기 카탈로그에는 엔진 요청이 없어야 한다. 중급 모바일과 정한 네트워크 조건에서 캐시 없는 게임 진입 P95 3초 이내, 물리 장면 30 FPS 이상을 목표로 하고 압축 바이트, P95 프레임 시간과 반복 게임 전환 후 메모리 추세도 기록한다. |
| 모바일과 접근성 | 세로·가로에서 회전, 브라우저 주소창 변화, 최대화면 시작·복귀와 인앱 브라우저의 지원 제약을 확인한다. 클릭·터치 좌표와 보드가 일치하고, 화면 모드가 바뀌어도 진행 상태가 유지되어야 한다. 키보드와 화면 낭독 흐름을 핵심 화면에서 확인한다. |
| 테마와 언어 | 두 참가자의 언어를 서로 다르게 설정하고, 동시에 진행 중인 경기에서 테마·언어를 바꾼다. React와 엔진의 표시 변경, 지속 저장, 경기 ID와 보드 상태 유지, 상대 언어에 영향이 없는지 검증한다. |
| 비용과 서비스성 | 검증 비용은 무료 이용 한도 내에서 최소화한다. 반복 검증은 로컬에서 우선하고 배포 환경은 서로 다른 실제 네트워크와 강제 TURN 검증에 사용한다. 방 생성·신호·재접속 요청량과 TURN 발신량을 추적하고, 기존 프로젝트와 계정의 한도를 공유한다면 합산 사용량을 확인한다. 한도에 근접하면 추가 사용을 멈추고 검증 범위를 조정한다. |

## 합의할 주요 사항

| 시점 | 결정 |
| --- | --- |
| Phase 1 준비 | 합의한 기준에 따라 실제 테스트 기기·네트워크 조합을 기록한다. 배포 환경이 필요한 시점에 사용할 Cloudflare 계정의 가용 한도와 접근 범위를 확인한다. |

| 공개 전 | 도메인과 운영 예산, 개인정보 처리 범위와 보관 기간, 콘텐츠·자산 권리, 출시 여부를 결정한다. |
