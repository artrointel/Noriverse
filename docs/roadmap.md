# 개발 로드맵

## 진행 상태와 연결 검증

Phaser 오목과 충돌 장면, React의 화면·설정 관리, 로컬 Durable Object 방 서비스와 WebRTC 착수 동기화로 Phase 1을 시작했다. 이후 GitHub Pages와 공개 Worker를 연결해 친구 방을 열었으며, TURN과 기기·회선 조합별 반복 측정은 남아 있다. [연결 설계와 복구 절차](technical-design.md#시스템과-방의-수명) · [Pages 및 Worker 배포](../README.md#github-pages-첫-배포)

첫 로컬 검증에서 Chrome 두 세션으로 방 참여, 양쪽 착수 동기화, DataChannel 종료 후 동일 보드 복구, 재경기를 확인했다. 테스트의 WebRTC 환경에서는 Chrome의 mDNS 후보 기능을 끈 상태에서 직접 연결에 성공했다. 기본 브라우저 설정, 실기기, 서로 다른 네트워크에서의 연결 성공률과 P95는 별도 측정한다.

PC 인터넷 회선과 휴대폰 모바일 데이터 간 독립 STUN 테스트 1회에서 양방향 DataChannel이 연결됐다. 중계 없이 `srflx / srflx` 후보 쌍을 선택했고, PC에 응답을 적용한 뒤 약 6.1초 걸렸다. 사용자가 실제 경기에서 P2P 표시와 모바일 회선 변경 후 재연결을 확인했다. 여러 기기와 회선에서의 반복 측정은 남아 있다.

독립 LAN 테스트에서 샌드박스 안의 Chrome 두 세션은 mDNS 후보로 후보 쌍을 만들지 못했지만 사설 IPv4 주소를 비교하면 DataChannel 메시지가 왕복했다. 사용자 PC와 모바일은 기본 LAN 모드에서 후보 쌍이 없었고, STUN 모드에서는 데이터 왕복에 성공했다. 모바일에는 ICE 오류 701도 기록됐다. [독립 테스트 실행 및 진단](technical-design.md#시스템과-방의-수명)

## 단계별 목표

| 단계 | 주요 작업과 완료 기준 |
| --- | --- |
| Phase 0 · 기획과 설계 | 벤치마킹, 요구사항과 위험, 엔진·네트워크·UI 등 후보 설계와 검증 지표를 문서화했다. Phase 1의 범위와 검증 조건을 합의했다. |
| Phase 1 · 기술 타당성 | 최소 보드와 원형 충돌 장면으로 React와 엔진, WebRTC와 방 코드, 모바일 입력·회전·최대화면, 상태 동기화, 설정 변경을 검증한다. 실측에 근거해 엔진과 인프라를 선택한다. |
| Phase 2 · 플랫폼 기반 | 카탈로그, 등록과 지연 로딩, 파티·경기 생명주기, 공통 로비와 게임 셸, 테마·번역·화면 관리, 연결 복구를 만든다. 같은 로비에서 새 경기를 시작하고 환경 설정을 바꿔도 현재 경기가 유지되어야 한다. |
| Phase 3 · 초기 게임 | 자유룰 오목과 단순화한 알까기를 후보로 구현한다. 두 번째 게임은 공통 런타임을 복제하지 않고 등록, 게임별 설정, 규칙과 Scene을 추가해 동작해야 한다. 같은 방에서 두 게임 간 전환을 검증한다. |
| Phase 4 · 출시 준비 | 모바일 접근성·실기기 호환성, 장애 대응, 인프라 한도, 사용성, 성능을 개선한다. 실제 친구 그룹으로 검증하고 릴리스·롤백과 지표 수집 경로를 준비한 뒤 공개 여부를 결정한다. |
| Phase 5 · 콘텐츠 확장 | 공통 기능에서 확인된 재사용 요구를 반영하고 게임을 추가한다. |
| Phase 6 · 장기 기능 | 사용 지표를 근거로 공개방·매칭, 선택적 계정·프로필 및 성장 기능을 검토한다. |

## 구현된 플랫폼 기능

첫 방문 시 프로필이 없으면 이름 입력을 팝업으로 열고, **나중에**를 누르면 현재 방문 동안 건너뛸 수 있다. API를 연결하지 않은 Pages에서는 표시 이름을 브라우저 쿠키에 저장한다. 프로필 공유 링크에서 누적 시간, 게임별 합계와 최근 기록 20개를 조회할 수 있다. 프로필 레벨은 1에서 시작해 기록된 시간 3,600초마다 오른다. 승률은 승리 수를 승리·패배·무승부 전체로 나눈 값이며 전적은 브라우저가 제출한다. [프로필 저장 설계](technical-design.md#익명-프로필-저장)

게임은 지원하는 방식에 따라 **방 만들기**와 **혼자하기**로 진입한다. 한 기기에서 양쪽을 조작할 수 있는 게임은 혼자 연습하거나 기기를 번갈아 사용한다. 게임 진행 정보에는 현재 턴이나 점수와 초 단위 플레이 시간을 표시한다. 첫 방문은 브라우저 언어 목록과 시스템 테마를 사용한다.

상단 내비게이션의 **방 만들기**에서 게임을 고르면 해당 게임의 온라인 설정 화면으로 이동한다. 방제는 프로필 이름을 넣은 다섯 문구 중 하나로 시작하고, 주사위나 직접 입력으로 바꿀 수 있다. 방 만들기를 누르면 방 코드를 발급하고 설정한 방제를 대기실 제목에 표시한다.

방장이 결과 화면에서 대기실로 돌아가면 같은 경기 화면을 보고 있던 참가자들도 함께 이동한다. 방 코드와 설정, 랭킹 기록을 유지한 채 다음 경기를 준비한다.

대기실의 참가자 목록에는 대기실, 메인, 프로필, 게임처럼 현재 화면의 종류가 표시된다. 이 상태는 연결된 방의 참가자에게만 전달하며, 프로필 주소나 페이지 매개변수는 공유하지 않는다.

진행 중인 방은 상단 메뉴에서 결과 보기 버튼과 같은 강조 효과로 표시한다. 긴 방제는 버튼 폭을 유지한 채 순환한다. 새 친구 요청은 프로필과 친구 관리 버튼에 공통 알림 점으로 표시하고, 받은 요청을 확인하면 해당 브라우저에서 표시를 해제한다.

턴제 재경기에서는 직전 경기의 패자가 선공 색을 받는다. 체스는 백, 오목·오델로·알까기는 흑이 먼저 두며 기권과 시간 초과 패배도 반영한다. 무승부는 색을 유지한다.

오목에서는 3–3 허용 여부와 6목 인정 여부를 따로 선택한다. 3–3을 금지하면 한 수로 두 방향에 열린 삼을 만드는 흑 착수를 막으며, 5목 승리를 우선 판정한다. 기본값은 정확히 5목만 승리이며, 방의 설정은 양쪽과 재경기에 유지된다. [국제 오목 규칙](https://gomoku.renju.net/gomokurules/) · [3–3 규칙 참고](https://www.renju.net/rifrules/)

오델로는 상대 돌을 뒤집을 수 있는 위치만 허용한다. 둘 곳이 없으면 패스하고 양쪽 모두 둘 곳이 없을 때 점수를 확정한다. 모바일에서는 같은 위치를 두 번 탭해 착수한다. [오델로 공식 규칙](https://worldothello.org/about/about-othello/othello-rules/official-rules/english)

턴 제한시간은 프리셋 또는 1~3600초 중 직접 입력으로 정하며 기본값은 제한 없음이다. 진행 정보 버튼에 현재 턴과 카운트다운을 표시하고 마지막 3초에는 효과음을 재생한다. 시간이 다 되면 상대가 승리를 확정하거나 같은 턴에 15초를 추가할 수 있다. 친구 방은 호스트가 시계와 선택 권한을 판정한다. 참가자 화면이 시간 초과 상태에 머무르면 선택이나 최신 상태 요청을 다시 보내며, 늦게 온 이전 시계 상태로 되돌리지 않는다. 알까기는 돌이 움직이는 동안 시계를 멈춘다.

체스는 한 기기와 온라인 대전, 공통 턴 제한시간과 전적을 지원한다. 합법 수와 결과는 chess.js로 검증한다. 놀이버스에서는 3회 반복과 50수 규칙을 자동 무승부로 적용한다. 원목 보드와 체스 기물의 텍스처를 사용하고, 기물 이동은 선형으로 보간하며 잡힌 기물은 기울어지며 사라진다.

체스는 선택한 기물의 이미지 실루엣에 아웃라인을 입히고, 이동할 수 있는 빈 칸과 잡을 수 있는 칸을 서로 다른 모양으로 표시한다. 최근 수와 포커스 표시는 오목·오델로에서도 같은 Phaser 렌더링을 사용하며, 알까기의 조준 표시에도 같은 테두리 스타일을 적용한다. 모션 줄이기 설정에서는 표시가 즉시 나타난다.

오목·알까기는 목재 바둑판과 흑백 돌 이미지, 그림자와 물리 연출을 사용한다. 알까기 온라인 방에는 최대 4명이 참가할 수 있다. 기본 시작 돌은 한 사람당 5개로 3~7개까지 바꿀 수 있다. 고정·랜덤 배치와 세 가지 바둑판 크기를 지원하며, 세 크기의 물리 판정 한 변은 초기 기준에서 30% 늘렸다. 돌의 중심이 판을 벗어나면 제거한다. 2인전은 한쪽이 전멸하면 상대가 이기고 같은 샷에 양쪽이 전멸하면 무승부다. 3~4인 개인전에서는 돌을 모두 잃거나 시간 초과로 탈락하며, 최후 생존자가 이긴다. 재경기는 첫 탈락자부터 시작한다. 재연결 시에는 마지막 확정 배치와 진행 중인 발사를 받는다. [한국기원](https://m.baduk.or.kr/news/B02_view.asp?news_sum_no=18) · [다섯 돌 규칙](https://playfulo.com/ko/games/alkkagi) · [장외 판정](https://www.board-pan.com/guide-alkkagi.html)

개인 설정의 접힌 언어와 테마에서 현재 값을 확인할 수 있다. 배경음과 효과음 크기는 각각 저장하며, 볼륨을 유지한 채 한 번에 음소거할 수 있다.

친구 초대는 호스트의 방 자리와 친구 목록을 검증하고, 프로필의 WebSocket으로 접속 중인 화면에 전달한다. 접속을 유지하는 브라우저를 온라인으로 표시하며 친구 목록은 15초마다 갱신한다. 오프라인 친구는 접속 후에도 유효 시간 안에 초대를 받을 수 있다. 초대는 최대 3분간 유지된다.

공개 프로필 링크나 대기실에서 친구 요청을 보내고 상대가 수락하면 양쪽 목록에 등록된다. 어느 쪽에서든 삭제하면 두 목록에서 해제된다. 기존에 서로 추가한 친구는 유지한다. 대기실에서는 보낸 사람의 이름으로 새 요청을 하단에 알리고, 같은 방 참가자의 요청은 참가자 목록에서 바로 수락할 수 있다. 미처리 요청은 프로필의 친구 관리에서 수락하거나 거절할 수 있다. 온라인 상태와 현재 방은 접속 이벤트로 갱신하며, 비정상 단절 시에는 신호가 만료되면 오프라인으로 전환한다. 참가 화면은 서버가 입장 가능을 확인한 최근 방을 보여준다. 친구 목록에서는 친구가 접속 중인 방에 남은 자리나 이전에 예약된 자신의 자리가 있을 때 참가할 수 있다.

사천성은 최대 두 번 꺾이는 가로·세로 경로로 타일을 연결하는 퍼즐이다. 한 판에는 선택한 콘셉트의 Phaser 아틀라스와 전용 보드 배경을 적용한다. 초기 클래식 아틀라스를 제거해 현재 일곱 콘셉트를 지원하며 기본 선택은 랜덤이다. [KShisen 규칙](https://docs.kde.org/trunk_kf6/en/kshisen/kshisen/howto.html)

사천성 격자는 6×6, 8×8, 10×10, 12×12 중 고르며 권장 제한 시간은 각각 30초, 1분, 1분 45초, 2분 45초다. 타일 밀도는 기본 60%이고 30~100% 또는 랜덤으로 설정할 수 있다. 장애물 밀도의 기본값은 전체 칸의 20%이며, 0%를 선택하면 장애물이 없다. 짝수 개의 타일을 먼저 배정한 뒤 남는 공간까지만 장애물을 배치한다. 랜덤 밀도는 추첨한 타일 밀도에 이 상한을 적용한다. 장애물은 섞기에도 자리를 유지한다. 1초 안에 연속으로 짝을 제거하면 콤보가 올라간다.

방장은 게임 변경 팝업에서 현재 인원으로 플레이할 수 있는 게임을 라이브러리 카드로 고른다. 프로필은 경기 기록이 있는 게임만 표시한다. 저장에 실패한 경기 결과는 해당 프로필의 브라우저에 보관하고 프로필을 열거나 네트워크가 복구되면 재전송한다. 앱의 뒤로가기 링크는 브라우저의 이전 화면을 따르고, 주소로 직접 열었을 때는 화면별 기본 경로를 사용한다.

사천성 2~4인 방에서 대전과 협동을 고를 수 있다. 참가자 전원이 준비되면 공통 제한시간이 시작된다. 대전은 같은 배치의 보드를 각자 풀며 먼저 클리어한 사람이 이긴다. 협동은 보드를 공유하며 함께 클리어하면 전원이 이긴다. 시간이 끝날 때까지 클리어하지 못하면 전원이 패배한다. 힌트와 섞기는 기본 3회이며 0~5회까지 설정할 수 있다. 대전에서는 각자 횟수를 쓰고 협동에서는 공유한다. 섞기는 연결 가능한 짝이 남아 있을 때도 사용할 수 있다. 진행 중 처음 입장한 참가자는 대기실에서 다음 경기를 기다린다.

사천성 장애물 터치에는 0.5초의 흔들림과 두 번의 적색 점멸을, 타일 선택에는 노란 표시와 종이 효과음을 적용한다. 제거 연출은 테마별 입자와 타일 모션을 사용하며 콤보에 따라 입자 수, 연결선 광량과 지속 시간이 증가한다. 콤보 숫자와 `Combo!`는 한 장의 생성 이미지 아틀라스에서 조합한다. 모션 줄이기에서는 콤보 배너를 이동 없이 표시한다. 보드 아래 Phaser HUD는 하나의 공용 텍스처로 패널, 상태 아이콘, 섞기·힌트 버튼을 그리며, 각 테마에는 전용 카드 배경을 적용한다.

사천성 온라인 대전은 감정 표현 옆에 상대별 타일 제거 진행률을 표시한다. 상대 콤보는 기존 경기 상태를 통해 전달되며, 내 콤보보다 작고 고음이 줄어든 소리와 짧은 메아리로 들린다.

메모리는 사천성의 테마 아틀라스, 카드 앞·뒷면, 뒤집기 연출, HUD와 친구 방 흐름을 재사용한다. 라이브러리에는 뒤집힌 카드 사이에서 같은 여우 그림 두 장이 드러난 전용 썸네일을 사용한다. 4×4 또는 6×6 배치를 선택하고, GO 뒤 4초간 카드를 외운 다음 두 장씩 고른다. 짝이 맞으면 제거하고, 다르면 0.7초 뒤 다시 덮는다. 혼자 풀거나 2~4명이 동일한 배치로 대전하며, 제한시간은 외우는 시간 이후 각각 1분 30초 또는 3분이다.

별젤리(Jelly Orbit)는 혼자 연습하거나 2~4명이 생존 대전을 하는 오리지널 낙하 퍼즐이다. 7×11 보드에서 같은 색 젤리 네 개 이상을 가로·세로로 연결해 제거한다. 2연쇄부터 다음 생존 상대에게 운석을 보내고, 운석은 인접한 젤리 제거로 없앨 수 있다. 대전 참가자마다 같은 순서로 젤리가 나오며 마지막 생존자가 이긴다. 호스트는 입력과 낙하 시점에 상태를 확정하고, 조작이 몰리면 연속 스냅샷을 85ms 간격으로 합쳐 기존 중계 한도 안에서 전송한다. 재접속한 참여자는 최신 보드를 받는다. 원격 조작은 호스트 응답 후 표시하므로 실제망의 입력 지연은 후속 검증에서 함께 측정한다. Phaser 장면과 픽셀아트 애니메이션 아틀라스는 경기 진입 시 불러온다. [소거 기준 참고 · SEGA](https://puyo.sega.jp/portal/topics/info/20181217_001802/)

라이브러리에서 뿌요뿌요 또는 Puyo Puyo로 검색하면 별젤리가 나온다. 카드와 게임 설명은 낙하와 연쇄 방식의 유사성을 안내한다.

별젤리의 정면 픽셀아트는 대기·낙하·착지·소거를 한 장에서 읽는다. 현재 젤리 쌍의 착지 위치에는 같은 색의 반투명 젤리를 표시한다. 대전 HUD의 기본 탭은 상대 현황이며, 기존 방 스냅샷에서 착지한 젤리와 운석만 읽어 참가자별 미니 보드를 갱신한다. 내 상태 탭에는 제거한 젤리, 최대 연쇄, 대기 중인 운석이 표시된다. 연습에서는 내 상태가 바로 표시된다. 화면 버튼과 방향키 입력 모두 아래를 한 번 누르면 한 칸 내리고, 같은 젤리 쌍에서 0.5초 이내에 연속 두 번 누르면 즉시 낙하한다.

별젤리는 소거 연출을 약 0.58초간 보여준 다음 남은 젤리와 운석을 빈 칸으로 떨어뜨린다. 낙하가 끝난 뒤 다음 소거를 확인하고, 연쇄가 모두 끝나면 다음 젤리를 생성한다. 방 호스트는 보드별 단계와 마감 시각을 보내며, 다른 참가자는 자신의 보드를 계속 플레이할 수 있다. 재접속하면 진행 중인 단계부터 그린다.

별젤리 보드에는 우주 배경 다섯 가지와 일본의 벚꽃 정원, 한국의 감나무 한옥, 중국의 홍등 정자 배경을 사용한다. 경기 ID에 따라 기본 배경 한 장과 각각 다른 속도로 움직이는 투명 레이어 두 장을 고른다. 세 이미지를 실제 격자의 너비와 높이에 맞춰 배치하고, 정적인 픽셀 프레임으로 타일 안쪽에만 배경을 노출한다. 동작 줄이기 설정에서는 레이어를 고정한다. 젤리의 눈과 몸, 격자 창과 HUD 버튼의 원본 픽셀을 게임 좌표에서 동일한 2단위로 그린다. 젤리는 착지 후에도 각자 다른 간격으로 눈을 깜빡인다. 픽셀 스킨의 범위는 보드 내부 HUD와 탭이며, 경기 바깥의 공용 조작과 팝업에는 플랫폼의 테마를 적용한다.

개인 설정과 내 프로필에서 공개 접속 상태를 바꿀 수 있다. 오프라인을 선택하면 서버 프로필에 기록하며, 수동으로 온라인으로 돌아올 때까지 친구 목록의 방 공개와 게임 초대를 중지한다. 친구 목록의 마지막 접속 시각은 공개 온라인 연결이 시작되거나 온라인으로 직접 전환할 때 갱신한다. 숨김 상태로 접속하면 이전 공개 시각을 유지한다.

프로필의 친구 관리 버튼에 공개 온라인 인원과 전체 친구 수를 표시한다. 프로필은 방 조회를 건너뛰고 공개 접속 상태를 집계한다. 친구 목록과 초대 팝업에서는 참가 가능 방 정보도 조회한다.

캐치마인드는 혼자 연습과 2~4인 친구 방을 지원한다. 방장은 한국어·영어 제시어, 1·2·3분 맞히기 시간, 인당 출제 횟수, 힌트 간격(기본 30초), 다섯 그림 맵 또는 랜덤을 정한다. GO 뒤 출제자에게만 제시어를 2초 보여주고 제한시간을 시작한다. 글자 수, 분류, 제시어에 따라 색상 힌트를 순차 공개한다. 첫 정답자는 남은 시간에 따라 100~300점을 얻고 다음 출제 우선권을 갖는다. 출제권이 없거나 아무도 못 맞히면 출제권이 남은 사람 중 점수 상위자가 이어서 그린다. 동점은 누적 정답 시간이 짧은 순과 경기 시작 시 추첨한 순서로 가려 한 명만 승리한다. 펜·붓·분필·마커와 자유 굵기, 최근 사용 색, 획 단위 실행 취소·재실행을 지원한다. 그리기 입력은 묶어서 전송하고 재접속하면 그림과 점수를 복원한다.

캐치마인드는 그림 위에 시계와 제시어 배지를 표시하고, 아래의 투명한 Phaser HUD에 도구별 카툰 아이콘과 Jua 글꼴, 힌트와 점수를 배치한다. 정답 공개 전까지 맞히는 사람에게 제시어를 숨긴다. 테두리까지 그릴 수 있으며, 붓은 포인터 속도에 따라 굵기가 변한다. 지우개는 잉크만 지운다. 그리기 입력 취소 후에도 새 획을 시작할 수 있으며, 긴 그림의 복구 스냅샷은 방 중계 크기 안에 들어가도록 압축한다.

캐치마인드에서 제출한 답은 정오답과 관계없이 모든 참가자에게 기존 감정 표현 슬롯의 텍스트 말풍선으로 표시한다. 말풍선의 이름과 답에는 주아 글꼴을 쓰며 답은 슬롯 크기에 맞춰 줄바꿈하고 축소한다.

공통 경기 화면은 게임 정보와 전체화면 사이의 물음표 버튼에서 게임별 조작 도움말을 연다.

라이브러리는 한글·영문 검색과 인원·전략·액션 필터를 제공한다. 게임을 고르면 목록 위에 규칙 미리보기와 플레이 버튼이 열린다. 하트를 누른 게임은 즐겨찾기 탭과 프로필에 표시한다. 페이지당 카드 수는 안정적인 뷰포트 높이와 격자 크기로 계산한다.

라이어 게임은 3~4인 친구 방에서 비공개 역할 카드, 순서대로 힌트 제출, 비밀 투표를 지원한다. 최다 득표가 동률이거나 라이어를 지목하지 못하면 라이어가 이긴다. 라이어를 지목하면 한 번의 제시어 추측 기회를 주고, 틀리거나 제한시간이 지나면 시민이 이긴다. 역할과 투표 내용은 호스트가 관리하며 참가자별로 자기 카드와 투표만 전송한다.

라이어 게임 전용 Phaser HUD에 단계, 타이머, 비공개 카드와 방 내 라이어 누적 점수를 표시한다. 개발 환경의 대기실에서 방장은 비어 있는 자리에 입력 없는 테스트용 목업을 추가하거나 제거할 수 있다.

대기실과 경기 화면에 [방 랭킹보드](room-ranking.md)를 적용했다. 대기실 게임 카드의 참가자 목록 아래 오른쪽에 게임 설정, 방 게임 변경, 게임 시작, 방 나가기를 배치한다.

게임 변경, 설정, 프로필 편집과 경기 결과 등은 공통 팝업 배경과 닫기 동작을 사용한다.

공개 프로필과 내 프로필의 경험치 아래에 뱃지를 표시한다. 전체 뱃지 팝업은 획득과 미획득 탭을 제공하고, 미획득 이미지는 흑백으로 표시한다. 뱃지 이름·업적 설명·달성 기준은 [공용 명세](../packages/protocol/badges.ts)에 둔다. 게임 정복은 기존 온라인 전적에도 적용하며, 방 연승·역전·랭킹은 새로 완료한 실제 다인 경기부터 집계한다. 연승과 연패는 한 방에서 각자 참가한 경기 순서로 계산하며 무승부에서 끊긴다. 랭커는 실제 다인 경기 기록이 있는 방이 종료될 때 랭킹보드와 같은 기준으로 1명을 선정한다. 비공개 프로필 알림 연결은 새 뱃지와 획득일도 전달한다.

프로필 편집에서 지에나를 포함한 별길 탐사대 11종, 기본 아이콘 15종과 투명 또는 단색 배경을 미리 보고 저장할 수 있다. 별길 탐사대 아이콘을 고르면 탐사 역할과 짧은 소개가 표시되고, 도감에서 캐릭터마다 상세 이야기를 볼 수 있다. 세계관과 캐릭터 디자인은 [별길 탐사대 설정집](characters.md)에서 관리한다. 공개 프로필과 방 참가자 목록은 저장한 배경색을 적용하며, 이모지 말풍선은 캐릭터 레이어만 렌더링한다. 이모지 목록은 전용 효과음이 있는 항목을 재생 배지로 표시한다.

프로필 아이콘 설정과 개인설정은 공통 `Grouper`로 섹션을 접고 펼친다. 프로필 아이콘 설정은 구분선 형태로 캐릭터, 배경, 테두리를 나누며 처음에는 캐릭터를 열어둔다. 개인설정은 요약값을 표시하는 패널 형태를 사용한다.

내 프로필 하단의 관리 카드에서 삭제 확인 창을 연다. 삭제를 확인하면 공개 프로필, 전적, 친구 관계와 대기 중인 친구 요청을 삭제하고 브라우저 세션을 만료시킨다. 프로필 서버를 연결하지 않은 배포에서는 브라우저 쿠키의 프로필과 터치 설정을 지운다.

배경음은 총 37곡으로, 홈·로비에서 고르는 34곡과 경기 전용 3곡이 있다. 배경음과 공용 UI·게임 효과음은 첫 상호작용 이후 Web Audio로 합성한다. 사운드 설정은 곡 이름 아래에 분위기 태그를 표시하며, 곡 이름을 누르면 다른 곡을 무작위로 선택한다. 경기에서는 게임별 후보를 사용하고, 재경기가 시작되면 직전 곡을 제외하고 고른다. 스윙 재즈, 탱고, 딥 하우스, 살사 등 템포와 반주가 서로 다른 배경음 10곡을 추가했다.

한 곡이 10분 연속 재생되면 현재 화면의 후보 중 다른 곡으로 자동 전환한다. 음소거, 탭 숨김 또는 오디오 일시 정지 후에는 연속 시간을 다시 센다. 모든 곡 전환에서 약 0.85초 동안 두 곡의 음량을 교차 페이드한다.

모든 경기 화면의 우측 하단에 감정 표현을 제공한다. 반투명 팝업의 탭은 최근, 기본, 이모지 순이다. 이모지 탭에서 한글·영문 이름이나 관련어로 검색한 이모지를 추가할 수 있다. 최근 이모지 최대 5개와 추가한 이모지는 브라우저 쿠키에 저장한다. 방장은 경기 시작 시 참가자 순서대로 네 모서리에 고정 슬롯을 배정한다. 4인을 초과하면 같은 순서로 슬롯을 돌려 쓰고, 같은 슬롯의 이전 표현은 최신 표현으로 교체한다. 말풍선은 3초간 표시하며 등장할 때 두 번 커지고, 기본 이모지 17개는 참가자 각자의 효과음 설정에 따라 전용 효과음이 함께 난다. 찰싹은 110ms 간격으로 두 번 재생한다. 기본 탭의 이미지는 후속 작업이다.

모든 게임은 Phaser 보드 위에서 투명 픽셀아트 아틀라스와 효과음으로 3·2·1·GO 및 한글·영문 종료 안내를 표시한다. 온라인은 참가자의 화면이 준비되면 호스트가 공통 시작 시각을 정한다. 입력과 경기 시간은 GO가 끝난 뒤 시작한다. 경기가 끝나면 안내가 1.5초간 표시되고 0.5초 뒤 결과가 열린다. 참가자는 결과 화면에서 방장에게 재경기를 요청할 수 있고 종료 후에도 이모지를 보낼 수 있다. 상태 초기화 중에도 전체화면 컨테이너를 유지한다. 연습 모드는 종료 버튼을 제공하며 프로필 플레이 시간·전적·레벨과 최근 경기 목록에서 제외한다. 결과 보기에는 강조 스타일을 적용한다. 상단 정보에는 실제 모드·테마·격자 크기나 경기장 프리셋을 표시한다.

프로필 터치 효과는 은은한 파티클, 물결, 꽃잎 회오리, 픽셀 반딧불, 픽셀 폭발과 끄기를 지원한다. 선택한 항목의 오른쪽에서 표본을 반복 재생하고 기기별 표시 토글을 제공한다. 직접 연결된 참가자가 같은 보드를 쓰는 경기에서만 정규화한 터치 좌표와 효과를 공유한다. 개인 보드에서는 각자 자신의 터치 효과를 본다. 미리보기와 경기 모두 재생마다 각 입자의 방향, 거리, 속도와 크기를 바꾼다. 픽셀 효과는 사각 실루엣을 유지하면서 위치와 투명도를 연속 보간한다. 다섯 효과는 픽셀 폭발의 기존 크기에서 20% 줄인 표시 범위를 공통 기준으로 삼는다.

오목과 체스는 마우스와 터치의 첫 목적지 입력에 반투명 기물을 표시하고, 같은 자리를 한 번 더 선택하면 착수한다. 두 게임의 도우미 표시는 녹색 계열을 사용한다. 온라인 체스의 상대 턴에는 상대 기물을 선택해 합법적인 목적지를 회색으로 볼 수 있다.

저장소 리팩토링에서 게임 ID와 방 정원을 공용 프로토콜에 모았다. 공통 경기 화면은 입장한 게임의 Phaser 씬을 따로 로딩하고, 오목·오델로·체스는 터치와 마우스 좌표를 수로 바꾸는 입력 모듈을 공유한다. 로컬 경기 상태 전이, 온라인 경기 스냅샷 검증, 프로필 상태 관리를 화면에서 분리했다. 방 HTTP 라우터와 Durable Object 구현을 분리했으며 워커 바인딩, 기존 방 메시지 형식과 저장 구조는 유지했다.

게임 설정 페이지와 대기실의 방장용 설정 팝업은 섹션으로 나뉜 같은 규칙 편집기를 사용한다. 사천성은 고정 밀도에서 타일, 장애물, 빈 칸의 개수를 즉시 보여 준다. 사천성 보드는 외곽 색상을 고정하고 브라우저의 자동 어둡게 처리를 피하도록 설정한다. 대기실 상단의 게임 카드에는 현재 규칙을 표시하며, 방장의 경기 시작 버튼은 참가자의 연결을 기다린다. 대기실 배경과 참가자별 공개 전적은 선택한 게임을 따른다.

손님이 진행 중인 경기에서 끊기면 같은 브라우저의 홈에 재입장 버튼이 나타난다. 방 코드로도 다시 들어갈 수 있다. 방장이 게임을 바꾸면 기존 경기만 초기화하며, 완료하지 않은 경기는 전적에 기록하지 않는다. 온라인 경기에는 내 차례 표시와 알림음을 제공한다. 체스 게임 정보에는 흑백별로 잡힌 기물을 집계하고, 승격 선택창은 보드 안에서 퀸, 룩, 비숍, 나이트를 제공한다. 알까기 돌과 체스 기물의 선택에 공용 밝기 애니메이션을 적용한다.

게임 변경으로 이전 손님 자리가 해제된 경우, 접속 중인 방장과 빈자리가 있으면 최근 방에 계속 표시하며 기존 방 코드로 한 번에 다시 들어갈 수 있다. 캐치마인드와 라이어 게임으로 바꾸면 제시어 언어의 기본값은 방장의 화면 언어를 따른다. 메모리와 사천성 대전 결과는 상대의 기권으로 끝난 경기와 보드를 먼저 완성한 경기를 구분한다.

경기 중 설정에서 안티에일리어싱과 해상도를 조절한다. 안티에일리어싱은 기본값이 켜짐이며 다음 경기부터 적용한다. 사천성의 화면 비율에는 HUD가 포함된다. [자동 해상도와 화면 방향](technical-design.md#모바일-최대화면과-화면-방향)

경기 정보는 방 참가자의 프로필과 담당 색을 표시한다. 보드와 조작 영역을 감싸는 카드는 콘텐츠 크기에 맞추고 투명하게 표시해 게임별 배경을 드러낸다. 결과 팝업은 공용 블러와 테마별 밝기 오버레이를 적용하며, 팝업 밖에서도 마지막 보드 상태를 볼 수 있다.

고정 내비게이션에는 테마 표면색을 70%로 적용하고 지나는 페이지를 블러 처리한다. 대기실 반응은 내비게이션 아래의 가시 영역 네 모서리를 사용한다.

## 햄버거 타이쿤

혼자하기, 2~4인 개인 대전·협동, 2~8인 팀 대전을 구현했다. [햄버거 타이쿤 기획서](burger-tycoon.md)에서 조리·정산, 성장·난이도, 카드 및 렌더링 기준을 관리한다. [개발용 밸런스 화면](burger-tycoon.md#개발용-밸런스-화면)도 기획서에서 열 수 있다.

해금·매진 카드의 XP 보정을 주문 정산에 적용했다. 개발용 밸런스 화면에서 카드별 보정과 내부 난이도 1~20단계, 손님 정산 기준과 예시를 확인할 수 있다.

고화력과 자동화에 2단계 카드를 추가했다. 자동 뒤집기와 트레이 이송은 호스트가 주방 시계로 처리한다. [그릴 카드 규칙](burger-tycoon.md#전체-카드-설명)

자동화 그릴 2에서도 패티를 직접 뒤집거나 철판·트레이·조립대 사이에서 옮길 수 있다.

그릴 카드 등장 레벨과 트레이가 가득 찼을 때의 가열 동작을 조정했다. 두 번째 조립대를 확장하는 자동 조립 카드와 경기 복구를 추가했다. [자동 조립 규칙](burger-tycoon.md#자동-조립)

음료 해금 카드의 XP 보정을 조정하고, 버거 보관대를 확장하는 주문 보관대 카드를 추가했다. 주문 속재료 상한을 바꾸는 카드의 등장 레벨도 조정했다. [카드 규칙](burger-tycoon.md#전체-카드-설명)

조립기의 작동과 상태 표시는 본체에 내장된 버튼과 LED를 사용한다. [자동 조립](burger-tycoon.md#자동-조립)

수동 조립 대상 표시를 슬롯 아래로 옮겼다. [입력과 표시](burger-tycoon.md#입력과-표시)

자동 조립기를 설치하면 왼쪽만 수동 조립 대상으로 선택할 수 있다. [자동 조립](burger-tycoon.md#자동-조립)

협동 주문 제출음을 동기화하고 가득 찬 패티 트레이의 입력 피드백을 추가했다. 초기 손님 방문 간격을 조정했다. [입력과 표시](burger-tycoon.md#입력과-표시) · [내부 난이도와 무한 모드](burger-tycoon.md#내부-난이도와-무한-모드)

응대 칸의 제출 버튼을 빨간 호출 벨로 교체했다. [입력과 표시](burger-tycoon.md#입력과-표시)

레벨업 카드의 면과 메뉴판을 교체하고, 열고 닫을 때 이동과 페이드를 적용했다. [운영 규칙](burger-tycoon.md#운영-규칙)

확정된 레벨업 카드가 커지며 선택 창이 페이드아웃된다. 공동 주방을 쓰는 참가자는 같은 확정 연출을 본다.

게임 HUD의 매장 상태 창에서 현재 적용 중인 카드 효과를 확인할 수 있다. 빈 대기줄에서는 짧고 맑은 전용 벨소리와 함께 다음 손님을 앞당길 수 있다. [운영 규칙](burger-tycoon.md#운영-규칙) · [입력과 표시](burger-tycoon.md#입력과-표시)

패티 트레이의 짧은 탭으로 맨 위 패티를 옮기고, 0.33초 동안 눌러 트레이를 연다. 버거를 응대 칸에 올린 동안에도 원래 조립 칸을 쓸 수 있다. [입력과 표시](burger-tycoon.md#입력과-표시)

철판의 패티에 타기 직전 경고를 추가했다. 4인 대전에서 일부 참가자가 시작 시각을 받지 못하는 경로를 재현했고, 방장이 준비 신호를 다시 받은 참가자에게 최신 경기 상태를 보내도록 수정했다. [조리 기준](burger-tycoon.md#운영-규칙)

인게임 설명서 왼쪽에 튜토리얼과 카드 클립을 추가했다. 카드 쪽에서는 그릴 강화, 빗자루, 자동 조립, 보관대, 해금과 매진을 그림과 함께 안내한다. [설명서 열기와 조작](burger-tycoon.md#입력과-표시)

응대 칸에서 보관대로, 보관대에서 수동 조립 칸으로 포장 버거를 옮길 수 있다. 패티 굽기를 색과 사선으로 구분하고, 탄 자국을 닦는 방법을 튜토리얼에 추가했다. [철판 및 보관대 조작](burger-tycoon.md#입력과-표시)

탄 자국을 여러 번 눌러 청소를 앞당길 수 있고, 협동은 두 번째 조립대가 열린 채 시작한다. 튜토리얼 첫 장에 영업 전 패티 준비를 추가했다. [운영 규칙](burger-tycoon.md#운영-규칙) · [설명서](burger-tycoon.md#입력과-표시)

보관대 음식은 휴지통에 놓을 때 폐기하며 빈 공간에 놓으면 원래 칸으로 돌아간다. 무한 모드의 남은 영업시간 비축 상한을 3분으로 늘렸다. [보관대 조작](burger-tycoon.md#입력과-표시) · [무한 모드](burger-tycoon.md#무한-모드)

매진 카드의 추첨 가중치를 절반으로 낮췄다. 주문과 굽기가 모두 맞으면 정가의 20%를 팁으로 지급하고 경험치에도 20% 보너스를 적용한다. [카드 규칙](burger-tycoon.md#전체-카드-설명) · [손님 보상](burger-tycoon.md#손님-보상)

팀 대전 대기실에서 참가자는 팀을 이동할 수 있고 방장은 팀을 추가하거나 빈 팀을 닫을 수 있다. 최대 네 주방이 팀별 매출로 경쟁한다. Worker 좌석 정원을 경기 방식에 맞춰 저장하며, 중계 참가자가 많은 방은 기존 전송 한도 안에서 스냅샷 간격을 조정한다. [팀 대전](burger-tycoon.md#팀-대전)

개발용 목업 명단과 팀 배치를 대기실 참가자에게 함께 동기화한다. 방장은 목업의 팀을 직접 설정할 수 있다. 자동으로 열린 빈 팀은 인원이 줄면 접고, 경기 중 들어온 실제 참가자는 다음 경기부터 배정한다.

## 두더지게임

두더지게임(Star Bop)은 3×3·4×4 격자에서 별길 탐사대 여섯 캐릭터를 잡는 혼자 연습 및 2~4인 점수 대전이다. 제한시간은 30·60·90초를 선택한다. 무한 모드는 60초에서 시작하고 캐릭터를 잡으면 시간을 얻는다. 진행할수록 등장 간격과 머무는 시간이 짧아지고 추가 시간도 줄어들며, 한 판은 최대 180초다. 가짜는 20점 감점과 무한 모드 1.6초 차감, 암석 캐릭터는 2~3회 타격이 필요하다. 30콤보마다 5초간 배율 2를 득점과 감점에 적용한다. 별 달린 캐릭터를 잡으면 3초간 거대 캐릭터를 연타할 수 있다. 대전에서는 다음 플레이 중인 상대에게 15콤보마다 가짜를 보내고, 피버나 거대 이벤트로 별안개를 보낸다. 거대 이벤트는 가짜도 보낸다. 방장은 타격과 점수, 타이머를 판정하고 기존 친구 방 스냅샷으로 전달한다.

두더지게임의 [이미지 리소스](../apps/web/src/assets/mole/)는 기본 ImageGen으로 생성했다. 프롬프트는 보라색 우주 정원 보드, 탐사대와 장난감 망치의 가로 표지, 솔오리·토링·꼬미·탈각이·빌몽·지에나의 평상시·놀란 표정 투명 스프라이트, 구멍·초승달 망치·금빛 별 터짐·보라색 계기판의 투명 소품 아틀라스로 구성했다. Web Audio는 망치·암석·가짜·거대 이벤트·피버·별안개 효과음과 전용곡 별정원 행진곡을 합성한다.

보드에는 보랏빛 석재 바닥 위로 별안개가 흐르고 양쪽 수풀이 흔들린다. 새 ImageGen 프롬프트는 정원 석재와 이끼, 투명 청록·보라 수풀, 투명 별안개와 포자, 탐사대 여섯 종의 등장·숨기 및 눈깜빡임·피격 자세를 요청했다. 캐릭터별 아틀라스에 여섯 프레임을 저장한다. 망치는 네 가지 궤적으로 내려치며 접촉 시 피격과 효과음을 재생한다. 가짜는 밝은 테두리를 두른 빨간 정지 배지로 표시한다. 대전 HUD는 상대 점수를 계속 표시하고 상대 타격·특수 이벤트·피버는 낮은 음량과 필터를 적용해 들려준다.

두더지게임은 첫 등장부터 두 마리가 함께 나오고, 진행 중에도 둘이 함께 나올 수 있다. 캐릭터가 머무는 시간을 늘리고, 후반에도 등장 간격과 머무는 시간이 완만하게 줄도록 조정했다. 캐릭터 수가 늘어난 만큼 무한 모드의 추가 시간을 조정하고 3분 상한을 유지한다.

피버가 시작하면 «피버타임!» 또는 «FEVER TIME!» 타이틀이 화면 중앙에 0.5초 나타난다. ImageGen 프롬프트는 투명 배경에 금빛 글자, 보라 외곽선과 청록 속도 장식을 요청했다. 피버 중 해당 참가자의 남은 시간 카운트다운이 멈추고 화면이 밝아지며 외곽에 속도선이 흐른다. 무한 모드 타격에 따른 시간 보너스와 감점은 계속 적용한다. 망치는 손잡이를 축으로 회전하며 헤드가 목표에 닿을 때 피격 효과를 재생한다.

## MVP 제안

공개 MVP는 **두 사람이 방 하나에서 오목과 알까기를 오가며 플레이**하는 범위를 권한다. 둘 다 익숙한 규칙이고, 턴제 상태와 물리 상태의 차이로 공통 계층을 검증할 수 있다. 내부 테스트는 오목 한 종으로 시작하고, 알까기는 물리와 입력 최소 기능부터 구현한다. 출시 일정이나 검증 결과에 따라 한 종만 공개하고 두 번째 게임은 내부 검증에 쓰는 대안도 있다. 그 경우 게임 전환에 대한 사용자 가설은 두 번째 게임 공개 뒤 확인한다.

- 게임 라이브러리와 상세·규칙, 익명 닉네임, 1:1 사설 방, 링크 또는 코드 참가, 최소 대기 로비, 플레이, 결과, 재경기, 같은 방의 게임 전환
- 신뢰성 있는 턴제 동기화와 호스트 물리 상태 전달, TURN, 단기 재접속과 스냅샷 복구, 호스트 이탈 안내
- 한국어·영어, 라이트·다크·시스템 테마, PC와 모바일 입력, 양방향 레이아웃 및 페이지 내 확장과 지원되는 환경의 네이티브 최대화면
- 기본 접근성, 오류 원인 안내, 운영용 연결·비용 지표

싱글플레이와 AI, 공개방·계정·순위표, 채팅, 큰 파티·팀, 비공개 정보 게임, 장기 세션 저장과 호스트 이전은 초기 공개 MVP 제안에서 제외했다. 이후 도입한 기능은 위의 구현 내역에 있으며, 서비스 전체 랭킹은 [장기 검토 항목](long-term.md)에 둔다.

## Phase 1 검증 범위와 기준

Phaser 4.2.1과 Cloudflare 방 인프라·STUN/TURN을 첫 후보로 검증한다. 오목 보드로 방 참가·착수·상태 복구를, 작은 원형 충돌 장면으로 물리·렌더링·터치 입력을 검증한다. 아래 수치는 합의한 초기 목표이며 표본 수와 기기·네트워크별 결과를 함께 기록한다.

| 검증 | 방법과 초기 목표 |
| --- | --- |
| 초대 및 P2P | PC Chrome·Edge·Firefox와 macOS Safari, iPhone Safari, Android Chrome 중 실제 접속 쌍을 정한다. 동일 Wi-Fi는 대조군으로 두고 Wi-Fi ↔ LTE/5G, 상이한 인터넷 회선 및 가능하면 제한망, 강제 TURN/TLS를 포함한다. 여러 네트워크에서 적어도 60회 유효 방 참가를 시도해 성공률 목표는 95% 이상, 사용자가 참가를 누른 뒤 플레이 가능까지 P95 8초 이내다. 네트워크·기기별 표본 수, 최초 직접 성공, 지연 복귀, 중계 연결을 별도 보고한다. |
| 신호와 복구 | 정상·만료·정원 초과·버전 불일치, 손님 백그라운드/네트워크 전환, 호스트 백그라운드/종료, 중복 입력과 연결 재시도를 검증한다. 단절 전후 마지막 확정 상태가 일치하고, 호스트 장기 이탈은 유예 후 중단 처리되어야 한다. |
| 엔진 통합 | 같은 크기·리소스의 장면에서 Phaser 4.2.1을 우선 측정해 필요 시 3.90 또는 Excalibur와 비교한다. 초기 카탈로그에는 엔진 요청이 없어야 한다. 중급 모바일과 정한 네트워크 조건에서 캐시 없는 게임 진입 P95 3초 이내, 물리 장면 30 FPS 이상을 목표로 하고 압축 바이트, P95 프레임 시간과 반복 게임 전환 후 메모리 추세도 기록한다. |
| 모바일과 접근성 | 세로·가로에서 회전, 브라우저 주소창 변화, 최대화면 시작·복귀와 인앱 브라우저의 지원 제약을 확인한다. 클릭·터치 좌표와 보드가 일치하고, 화면 모드가 바뀌어도 진행 상태가 유지되어야 한다. 키보드와 화면 낭독 흐름을 핵심 화면에서 확인한다. |
| 테마와 언어 | 두 참가자의 언어를 서로 다르게 설정하고, 동시에 진행 중인 경기에서 테마·언어를 바꾼다. React와 엔진의 표시 변경, 지속 저장, 경기 ID와 보드 상태 유지, 상대 언어에 영향이 없는지 검증한다. |
| 비용과 서비스성 | 검증 비용은 무료 이용 한도 내에서 최소화한다. 반복 검증은 로컬에서 우선하고 배포 환경은 서로 다른 실제 네트워크와 강제 TURN 검증에 사용한다. 방 생성·신호·재접속 요청량과 TURN 발신량을 추적하고, 기존 프로젝트와 계정의 한도를 공유한다면 합산 사용량을 확인한다. 한도에 근접하면 추가 사용을 멈추고 검증 범위를 조정한다. |

## 합의할 주요 사항

| 시점 | 결정 |
| --- | --- |
| Phase 1 준비 | 합의한 기준에 따라 실제 테스트 기기·네트워크 조합을 기록한다. 배포 환경이 필요한 시점에 사용할 Cloudflare 계정의 가용 한도와 접근 범위를 확인한다. |
| Phase 1 종료 | 실측을 바탕으로 엔진·인프라·호환 브라우저 범위, 연결·모바일·로딩 기준, 초기 배포 방식을 채택한다. |
| Phase 2 시작 전 | 방 코드·초대 TTL, 자리 유지와 호스트 유예 시간, 방 잠금과 손님 제거 정책, 인앱 브라우저 지원 범위, 오류 지표 보존 기간을 정한다. |
| Phase 3 시작 전 | MVP 게임 두 종과 세부 규칙, 둘째 게임의 공개 여부, 디자인과 브랜드 방향 및 접근성 목표를 결정한다. |
| 공개 전 | 도메인과 운영 예산, 개인정보 처리 범위와 보관 기간, 콘텐츠·자산 권리, 출시 여부를 결정한다. |
