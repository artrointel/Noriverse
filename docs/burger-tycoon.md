# 햄버거 타이쿤

우주 여행 중 배가 고파진 별길 탐사대가 들르는 햄버거 가게를 운영한다. 주문을 확인하고, 여러 패티를 굽는 동안 버거와 음료를 조립해 전달한다. 손님의 주문을 받아 조리해 건네는 흐름은 [붕어빵 타이쿤 소개](https://play.google.com/store/apps/details?hl=ko&id=com.arumgames.bungeoppang)를 참고했다.

| 항목 | 규칙 |
| --- | --- |
| 인원과 시간 | 혼자하기 또는 2~4인 대전. 3·5·7분 중 선택한다. 대전은 참가자마다 독립 주방에서 운영하며, 영업 종료 시 최고 매출이 승리한다. 최고 매출 동률은 무승부로 기록한다. |
| 손님 줄 | 최대 4명이 각자 타이머를 갖고 대기한다. 주문은 빵과 패티를 포함하고 재료 7개, 종류별 2개까지 요청한다. 첫 주문은 기본 버거이며, 응대 2건마다 주문 난도가 올라간다. 주문이 복잡해지고 대기시간과 방문 간격이 짧아진다. |
| 패티 | 2행 4열의 철판에서 양면을 따로 가열한다. 7초당 한 면 100%에 도달한다. 양쪽 면이 각각 50% 이상이면 평균이 가까운 레어 70%, 미디움 100%, 웰던 130%로 판정한다. 어느 한 면이 최대치인 200%에 도달하면 탄다. 굽기 단계는 패티의 색으로 읽는다. |
| 두 조립 칸 | 포장지 → 바닥 빵 → 패티와 토핑 → 같은 종류의 윗빵 → 포장 순서다. 선택된 칸을 다시 누르면 맨 위 재료를 제거하며, 패티는 출발 위치나 빈 보관 공간으로 돌아간다. 포장하면 조립이 확정된다. |
| 음료 | 콜라와 사이다 중 주문에 맞는 노즐을 2초 열면 100%가 찬다. 75·100·125%에 가장 가까운 사이즈로 판정한다. 컵과 주문 말풍선에는 같은 세 가지 액체 높이를 표시한다. 200%에 도달하면 컵이 비워진다. |
| 매출 | 빵 두 층과 층별 재료·굽기를 비교한다. 동일 위치의 일치를 두 주문 길이의 기하평균으로 나눠 코사인 유사도를 구한다. 같은 패티의 굽기 차이는 절반만 인정한다. 음료는 종류 58%, 사이즈 42%를 일치점수로 계산한다. 각 항목은 정확하면 정가, 일부만 맞으면 정가 × 0.56 × 유사도³을 지급한다. 메뉴가 복잡할수록 정가가 높다. |
| 콤보 | 주문 전체가 정확하면 콤보가 이어진다. 일부만 맞거나 손님이 기다리다 떠나면 콤보가 끊긴다. 5콤보마다 10초 피버를 발동해 이후 제출 가격을 두 배로 만든다. 진행 중 다시 발동하면 남은 피버 시간을 5초로 재설정한다. |

## 입력과 표시

가로 3:2 화면에서 조리대 위로 손님이 왼쪽에서 오른쪽으로 이동해 줄을 선다. 맨 오른쪽 손님이 응대 대상이며, 손님마다 머리 위에 주문한 버거를 쌓은 형태로 표시한다. 아래 HUD의 첫 줄은 재료 선반이고, 둘째 줄은 철판, 두 칸 패티 트레이, 조립대, 음료 기계, 응대 칸 순서다.

패티는 드래그로 옮기고 두 번 눌러 뒤집는다. 트레이의 두 칸은 각각 맨 위부터 꺼낸다. 조립 칸에 포장지와 바닥 빵을 깔고 말풍선의 버거를 아래부터 따라 만든다. 바닥 빵에 패티를 쌓으면 같은 빵 선택으로 윗빵을 올릴 수 있다. 조립 칸을 두 번 눌러 포장한다. 노즐을 누르면 음료가 나오고 다시 누르면 멈춘다. 포장된 버거와 음료를 단일 응대 칸에 준비하고, 제출 버튼으로 맨 앞 손님에게 건넨다. 응대 칸의 음식은 누르거나 끌어 되돌리고, 쓰레기통에 끌어 버린다. 맨 앞 손님이 떠나도 준비한 음식은 응대 칸에 유지된다.

## 리소스와 동기화

[버거 타이쿤 이미지](../apps/web/src/assets/burger/)는 내장 ImageGen으로 생성했다. 매장과 주방, 재료와 굽기 단계, 별길 탐사대 손님 스프라이트는 카툰 원본을 사용한다. 입력 구역은 렌더링에서 숨기고, 손님이 말하는 약 2초 동안 기존 말풍선의 주문 그림 자리에 대사를 표시한다.

작업대의 재료통 열두 개와 철판·트레이·도마·음료 기계·응대 쟁반은 같은 시점과 조명 아래 그렸다. 마름모 포장지와 손님 네 종류의 정면 대기·눈깜빡임·오른쪽 걷기 네 프레임은 독립 이미지다. 배경·캐릭터·재료·텍스트를 같은 격자에서 합성한다. 화면 위 픽셀 크기 슬라이더는 물리 화면 픽셀 기준 1~6칸을 비교하며, 기본값은 2칸이다. 현재 표시 영역에 맞춰 내부 3:2 해상도를 즉시 재계산한다. 이 값은 브라우저에 저장하거나 다른 참가자에게 전송하지 않는다. 손님 대기시간은 발치의 진행 막대로 표시한다. 조립용 재료를 누르면 통에서 도마까지 짧은 포물선을 그리며 이동한다. 익은 패티를 누르면 철판에서 트레이로 옮기고, 트레이의 패티를 누르면 도마로 옮긴다.

다리 전체가 보이는 테이블과 의자를 사용한다. 여섯 테이블을 두 줄에 배치하고 경기 시드에 따라 위치를 조금씩 바꾼다. 주문을 받은 손님은 응답 후 선착순으로 빈 좌석에 앉아 9~11초간 식사한 뒤 오른쪽으로 걸어 나간다. 방장의 일정으로 식사 상태를 유지하고, 연결 대기 중에는 기존 경기 시계와 함께 멈춘다.

주방 효과음은 원음을 잘라 제작한 CC0 실물 녹음으로 공용 효과음 볼륨을 사용한다. 종이 펴기·포장·폐기는 [Anthousai의 종이 녹음](https://freesound.org/people/Anthousai/sounds/398897/), 철판의 연속 소리는 [BenjaminNelan의 팬 녹음](https://freesound.org/people/BenjaminNelan/sounds/353124/), 집게·쟁반·누름은 [NichelleMedia의 금속 녹음](https://freesound.org/people/NichelleMedia/sounds/614853/), 탄산과 넘침은 [Anthousai의 음료 녹음](https://freesound.org/people/Anthousai/sounds/398985/), 제출과 시작·승리 알림은 [WillFitch1의 오븐 벨 녹음](https://freesound.org/people/WillFitch1/sounds/144883/)을 사용한다.

대전에서는 방장이 입력 순서, 타이머, 판정과 매출을 확정한다. 첫 주문과 주문 난수를 공유하고, 각 주방의 응대 속도에 따라 난도와 대기열이 따로 변한다. 물리 프레임 전송 없이 입력과 변경된 상태를 기존 방 통신으로 전달한다. 재접속 대기 중에는 타이머를 멈추고, 경기 종료 후 공용 결과·재경기·방 랭킹을 사용한다. 유사도 감점과 후반 대기시간은 실기기 대전의 주문 완료율을 확인한 뒤 조정할 수 있다.

주방 배경은 한 장의 카툰 이미지에 매장 타일 바닥과 준비대, 매립형 쓰레기통 입구, 8칸 보관대를 함께 그린다. 도마 위 포장지의 실제 너비를 버거보다 넓게 맞췄다. 오른쪽 패티 트레이는 소고기와 치킨을 독립적으로 쌓는다. 포장 버거를 하단 보관대에 놓으면 층순서대로 재료 아이콘이 표시되며, 보관된 버거를 누르면 응대 칸으로 꺼낸다. 쓰레기통으로 끌어 폐기하고 보관대의 버거는 위로 끌어도 폐기한다. 주문 말풍선은 Phaser에서 주문 크기에 맞춰 그리며, 전달 버튼은 접시 덮개 아이콘으로 표시한다. 게임 엔진 텍스트는 Sketch Jua를 사용한다.

손님 아틀라스는 원본에서 각 자세의 실루엣을 따로 추출하고, 발의 높이를 맞춘 뒤 투명 여백과 4px 간격을 두었다. 재료·패티는 새 카툰 원본에서 투명 가장자리의 잔여 픽셀을 정리해 패킹했다. Phaser 내부에서 스프라이트를 선형 샘플링한 다음, 합성된 화면은 지정된 물리 픽셀 크기로 확대한다. 공통 접촉 음영은 스프라이트의 불투명 범위와 바닥 위치에서 계산하며, 철판·도마·바닥의 강도와 들어 올린 높이를 반영한다. 같은 텍스처 기반 음영을 Canvas와 WebGL에 적용한다.
