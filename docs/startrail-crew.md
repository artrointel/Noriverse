# 별길 탐사대 게임 기획서

**별길 탐사대**는 친구와 함께 적대 외계인과 괴물이 장악한 행성에 내려가 주민을 구조하고 끊긴 항로를 되살리는 2D 탑다운 협동 슈팅 게임이다. 키보드로 이동하면서 마우스로 조준·사격한다. 한 사람이 시설을 복구하는 동안 다른 사람이 길을 지키는 순간이 협동의 중심이다.

한국어 게임명은 **별길 탐사대**로 확정했다. 영문 게임명 후보는 세계관의 탐사대 명칭인 **Startrail Crew**다. 게임 요구사항을 이 문서에서 계속 다듬고, 임무·전투·연출과 검증 기준을 합의한 뒤 개발을 시작한다. 수치는 [밸런스 테이블](startrail-crew-balance.md), 캐릭터의 원래 서사와 외형은 [별길 탐사대 설정집](characters.md)에서 관리한다.

## 세계관

별길 탐사대는 항성, 혜성, 위성을 닮은 작은 생명체들이 관측과 발견을 공유하며 미지의 우주로 항로를 넓혀 가는 모임이다. 적대 세력이 항로 중계소를 점거한 틈에 에너지를 먹는 괴물 무리가 몰려들면서 여러 행성의 전력과 통신이 끊긴다. 탐사대는 고립된 행성에 착륙해 주민을 구조하고 시설을 되찾아 안전한 길을 다시 연다. 임무를 마치면 궤도 지도의 연결선이 밝혀져 되찾은 항로와 다음 목적지를 보여준다.

Alien Swarm의 참고 범위는 탑다운 시점에서 여러 사람이 역할을 나누는 협동 경험이다. 탐사대원, 생물, 임무, 맵, 장비, UI와 사운드는 놀이버스 세계관에 맞춰 새로 설계한다. [Valve의 Alien Swarm 공식 Steam 페이지](https://store.steampowered.com/app/630/Alien_Swarm/)

## 핵심 플레이

1. **착륙한다.** 탐사대원을 고르고, 착륙 지점에서 이동과 사격을 익힌다.
2. **목적지로 전진한다.** 지형과 시설의 배치를 읽어 통로를 찾고, 적을 밀어내며 진행 경로 주변의 서브미션을 해결한다. 시설을 작동시키기 전에 주변을 정리할지, 바로 복구를 시작할지 결정한다.
3. **시설을 되찾는다.** 누구나 복구 패널을 조작할 수 있다. 조작 중에는 사격할 수 없고, 자리를 벗어나면 조작을 멈춘다. 작동을 시작하면 적이 몰려오므로 한 사람이 복구하고 다른 사람이 길을 지킨다.
4. **다음 구역으로 이동한다.** 필수 서브미션을 완료하고 종료 지점에 도착하면 다음 스테이지로 넘어간다. 마지막 스테이지를 마치면 복구 지점, 구조 여부, 소요 시간과 밝혀진 항로를 보여준다.

| 입력 | PC 기준 |
| --- | --- |
| 이동 | `WASD` 방향으로 이동한다. 조준 방향을 유지한 채 옆이나 뒤로 이동할 수 있다. |
| 카메라 | 게임 화면 위에서 휠을 내리면 기본 화면보다 가로·세로 최대 1.5배 넓게 볼 수 있다. 휠을 올리면 기본 크기까지 돌아온다. 탐험 시야와 조명 범위는 월드 좌표 기준으로 계산한다. |
| 조준·공격 | 마우스 커서가 조준 방향, 캐릭터의 응시 방향과 손전등 방향을 함께 결정한다. 좌클릭으로 주무기, 우클릭으로 부무기, `Alt`로 나이프를 사용한다. `F`로 손전등을 켜고 끈다. |
| 상호작용 | `E`로 패널을 조작하고, 구조 대상과 대화하거나, 행동 불능 상태인 동료를 일으킨다. |
| 구르기 | 이동 방향 키를 누른 채 `Space`를 누르면 그 방향으로 짧게 구른다. 도착 직전에 감속하고 일어설 때까지 이동 입력과 사격이 제한된다. |
| 미니맵 | `Tab`으로 숨김, 상세 지도, 오버레이를 순환한다. 탐사대원 위치와 발견한 지역을 확인할 수 있다. |

협동에서 한 명이 행동 불능이 되면 다른 사람이 가까이서 일으킬 수 있고, 탐사대 전원이 행동 불능이 되면 임무에 실패한다. 혼자하기는 같은 목표를 쓰며 적의 수와 출현 간격을 조정한다. 복구 장치를 잠시 떠났다가 다시 이어서 조작하는 방식도 검증한다.

## 2D 물리와 충돌

- 지면 위 중력이 없는 2D 물리 월드를 사용한다. 지형, 벽과 닫힌 문은 고정 충돌체로, 탐사대원과 몬스터, 밀 수 있는 상자와 장애물은 질량이 있는 동적 충돌체로 구성한다.
- 플레이어와 몬스터가 접촉해 밀고 밀릴 때 두 물체의 위치가 물리적으로 바뀐다. 키보드 이동과 AI 추격도 같은 충돌 월드를 거친다. 벽에 몰린 상황에서 겹침이나 통과 없이 밀어내기가 동작해야 한다.
- 공격이 적중하면 타격 방향으로 충격량을 적용한다. 같은 타격을 받더라도 가벼운 대상이 무거운 대상보다 더 빠르고 멀리 밀린다. 질량·감쇠·밀림 제한과 무기별 충격량은 밸런스 테이블에서 관리한다. 미끄러짐이 길어져 조작이 둔해지거나 팀원이 좁은 길을 장시간 막는 문제를 첫 검증에서 살핀다.
- **검증 후보는 Phaser 내장 Matter Physics**다. 질량과 동적 강체 충돌을 같은 월드에서 처리할 수 있는 점을 근거로 잡았다. 동시 적 수가 늘어날 때의 처리 시간과, 빠르게 움직이는 물체가 얇은 지형을 통과하지 않는지 확인한 뒤 채택한다. [Phaser Matter Physics 공식 문서](https://docs.phaser.io/phaser/concepts/physics/matter)

## 무기와 특수장비

장비는 근접무기, 주무기, 부무기와 공격 보조용 특수장비로 구성한다. 방어구는 향후 검토 항목이다. 장비별 피해·공격 속도·충격량을 독립적으로 조정할 수 있게 한다.

| 분류 | 지원 범위 |
| --- | --- |
| 근접무기 | 1-1은 나이프를 지급한다. 몽둥이·도끼·전기톱·광선검은 확장 후보이며 공격 범위, 속도와 밀어내기로 차이를 만든다. |
| 주무기 | 총기류를 사용한다. 현대식 소총·산탄총 계열부터 펄스총·에너지총 같은 SF 무기까지 사거리, 연사, 범위가 다른 무기를 갖춘다. |
| 부무기 | 권총·소형 펄스총 등의 총기류를 사용한다. 주무기와 다른 사거리와 조작감을 주는 보조 슬롯이다. |
| 특수장비 | 1-1은 고정 포탑, 호위 드론, 조명 수류탄을 지급한다. 고정 방어, 짧은 호위, 탐색 중 시야 확보를 나눠 맡는다. |

## 지도와 스테이지

한 임무는 맵이 서로 다른 여러 스테이지로 이어진다. 각 스테이지에는 시작 위치와 종료 위치가 있다. 주요 진행로 주변의 전력 복구, 통로 개방, 구조 같은 필수 서브미션을 해결하고 종료 위치에 도달해야 완료한다. 짧은 갈래길은 우회나 탐색에 쓰고 본선과 다시 연결한다. 스테이지가 바뀌면 이전 맵의 종료 장소를 다음 맵의 시작 장소로 이어서 탈환의 흐름을 보여준다.

배경은 전반적으로 어둡게 유지하고, 벽·기둥·격납 상자·문과 같은 지형지물로 통로와 전투 공간을 나눈다. 바닥의 배선, 조명의 흐름, 출구와 시설의 실루엣으로 어느 쪽으로 갈 수 있는지 읽히게 한다. 길 찾기의 기준은 배경만 보고도 다음 방향을 짐작할 수 있는지다.

화면 중앙의 미니맵은 전투 화면 위에 반투명으로 표시하며, 탐사대원별 현재 위치를 아이콘으로 구분한다. HUD의 임무 목표·복구 진행도·팀원 상태와 함께 엔진에서 렌더링한다.

## 아트, 픽셀 렌더러와 조명

- **텍스처.** 모든 이미지를 귀여운 카툰 스타일의 아틀라스로 제작한다. 캐릭터·몬스터·지형지물·장비·인게임 UI에 공통 팔레트, 빛 방향, 시점과 비례 기준을 적용한다. 윤곽은 색면과 명암으로 구분하고 아웃라인은 쓰지 않는다. 같은 대상의 프레임은 발밑 기준점을 맞추고 이웃 프레임이 비치지 않도록 여백을 둔다.
- **애니메이션.** 인게임 UI용 이미지는 정적으로 사용할 수 있다. 월드의 캐릭터·몬스터·장비·환경 오브젝트는 각 상태에 맞는 애니메이션을 갖춘다. 캐릭터와 몬스터는 대기·이동·공격·피격·행동 불능을, 문·패널·승강기는 작동·고장·복구를 움직임으로 보여준다.
- **픽셀 렌더러.** 바닥, 스프라이트, 이펙트, 조명과 안개까지 기기 해상도에서 먼저 합성한다. 카메라는 기기 픽셀 단위로 이동하고, 화면에 고정된 정수 픽셀 격자의 각 블록은 매 프레임 현재 프레임의 한 픽셀을 최근접으로 샘플링한다. 캔버스와 HUD는 같은 기기 픽셀 경계에 맞추며 HUD와 지도는 기기 해상도로 표시한다.
- **손전등과 시야.** 플레이어의 응시 방향에 맞춰 손전등 원뿔이 회전하고 정면을 밝힌다. 벽과 닫힌 문은 빛을 가려 뒤에 사각지대를 만든다. 조명이 닿지 않는 곳은 어둡게 유지하고, 팀원의 손전등과 복구된 시설 조명은 실제로 닿는 구역을 밝힌다. 조명 범위와 주변광은 통로와 위험 예고를 읽을 수 있게 조정한다.
- **간접광.** 테스트 페이지는 기본값으로 2D Radiance Cascades를 적용한다. 고정 조명, 손전등, 조명탄, 광선과 섬광을 같은 반사용 조명 버퍼에 누적하고 지형 색과 장애물 마스크를 함께 읽는다. 벽 앞면에서 확산 반사를 계산하고 강한 빛은 완만하게 압축한다. 가까운 층은 촘촘한 프로브에서 8방향을, 먼 두 층은 더 넓은 간격에서 32·128방향을 계산하고 투과율로 구간을 합친다. 평상시에는 월드 좌표에 맞춰 최근 결과를 재사용하며 순간 광원의 등장과 소멸은 즉시 반영한다. 탐험 안개는 간접광에도 적용되며, 벽을 비추는 광선은 해당 면을 잠시 드러낸다. 이때 탐험 기록은 그대로다. 추적 범위는 화면 안의 1회 반사까지다. [Radiance Cascades](https://github.com/Raikiri/RadianceCascadesPaper/blob/main/RadianceCascades.tex)
- **조명 테스트.** 화면 하단에서 Radiance Cascades, 근거리 레이, 벽 차폐 확산, 직접 조명을 비교할 수 있다. 직접광과 간접광의 표시 강도를 각각 0~100%로 조절한다. 기본값은 직접광 50%, 간접광 40%다. 간접광은 실제 광원 입력에서 계산하므로 직접광 표시 강도를 바꾸어도 유지된다. 간접광 단독 보기도 제공한다. WebGL2 경로가 사용 불가하면 CPU 확산으로 표시한다. FPS와 프레임 예산 대비 CPU 메인 스레드 시간 및 GPU 간접광 패스 시간을 표시한다. GPU 시간은 타이머 쿼리를 지원할 때 읽는다. [WebGL 타이머 쿼리](https://registry.khronos.org/webgl/extensions/EXT_disjoint_timer_query_webgl2/)
- **그림자.** 기본 설정은 물체별 자동이다. 총기, 탄피, 바닥 패드, 드론과 쓰러져 누운 몬스터에는 기본 그림자를 적용한다. 기립한 캐릭터, 몬스터, 크리스탈, 상자, 발전기, 문, 승강기 본체와 포탑 받침에는 회전 투영을 적용한다. 포탑은 받침에서 고른 광원별로 그림자를 한 쌍으로 합성한다. 총신은 기본 투영 형태를 사용하며 회전축을 받침 그림자의 소켓에 고정한다. 반전 구간에도 받침과 총신을 서로 연결한 채 두 쌍을 교차 페이드한다. 테스트 페이지의 비교 설정은 일반 물체와 포탑 받침의 투영 방식을 바꾼다.
- 기본 그림자는 현재 스프라이트 방향과 광원 쪽 실루엣 끝을 유지한 채 빛의 반대 방향으로 늘어난다. 회전 투영은 현재 스프라이트의 불투명한 하단 양 끝을 기준으로 위쪽을 광원 반대 방향으로 늘린다. 최소 투영 폭은 스프라이트의 원래 폭에 바닥면 높이 비율을 곱해 정한다. 이 폭에 도달하는 각도부터 보정 구간 끝까지 하단 기준이 위쪽으로 선형 이동한다. 90°에서는 이동량이 절반에 도달하고 투영 사각형이 직각을 이룬다. 좌우 반전은 80°~100°에서 두 실루엣을 선형으로 교차 페이드한다. 90°에서는 각각 50%를 합성한다. 보정 구간 끝에서는 보이는 실루엣의 폭에 같은 비율을 곱한 높이만큼 두 꼭짓점이 올라간다. 두 타입 모두 발이나 받침의 짧은 접촉 그림자를 포함한다. 가장 강한 광원 최대 두 개의 위치와 높이가 투영의 길이와 퍼지는 정도를 결정하며 공중 장비는 고도에 따라 바닥에 투영한다. WebGL과 Canvas에서 같은 투영 좌표를 사용한다. [물체별 임계값](startrail-crew-balance.md#회전-그림자-임계값)

| --- | --- | --- |
| **1-1 지표 중계소** | 남서쪽 착륙대에서 출발한다. 남쪽 정비로와 서쪽 얼음 통로 중 어느 쪽으로 가도 중앙 발전기에 닿는다. 서쪽 탐사 구역과 남동쪽 보급 창고는 막다른 지형이고, 중앙 발전기 북쪽 우회로는 종료 구역 쪽에서 동쪽 통로와 합류한다. | 발전기를 켜고 전력이 돌아오는 동안 방어한다. 복구가 끝나면 동쪽 차단문이 열리고 **지하 관측소행 승강기**에 도달해 완료한다. |

## 1-1 지표 중계소 구현

PC에서 [지표 중계소](http://localhost:5173/startrail/)를 연다. 상단에서 솔오리 또는 꼬미를 골라 **새 탐사**를 누른다. **동행 대원**을 켜면 다른 한 마리가 따라오며 전투 중 피해와 회복을 받을 수 있다. 1-1의 지도는 **36×28 타일**이다. 중앙 발전기 근처에서 `E`를 눌러 회로 퍼즐을 연다. 퍼즐을 완료하면 발전기가 가동된다. 제한 범위 안에서 발전기를 방어하면 차단문이 열리고, 승강기에 도착하면 결과가 표시된다.

- `WASD`로 이동하고 마우스로 조준한다. 좌클릭은 주무기, 우클릭은 부무기다. 다른 슬롯을 꺼내는 데 0.3초가 걸린다. `Alt`는 나이프 공격, `R`은 재장전이다. `F`는 손전등을 전환하고 좌상단 아이콘으로 현재 상태를 확인할 수 있다. 장착한 탄창에 탄이 남아 있어도 재장전하면 탄창을 통째로 교체한다.
- 착륙대 근처에는 데저트 이글과 의료총, 남쪽 정비로에는 AK 소총, 남동쪽 창고에는 산탄총이 있다. 가까이서 `E`를 누르면 들고 있던 주무기를 남은 탄약과 함께 내려놓고 바꿔 든다. 펄스 카빈의 광선은 일반 시야 밖에서도 도달한 지면을 발사 순간 밝힌다. 벽이 광선을 막으며, 일시적으로 비춘 지형은 지도에 기록되지 않는다. 산탄총은 총구 앞을 짧고 강하게 밝히며 사거리 끝까지 명중하지 않은 산탄은 사라진다.
- 의료총은 조준한 대상을 따라가는 곡선형 빔을 유지한다. 자신이나 다친 동행 대원은 회복시키고, 몬스터에게는 적중할 때마다 감속 확률을 판정한다. 체력이 가득하고 상태이상이 없는 아군에게는 탄을 쓰지 않는다. 자가 회복은 자기 캐릭터 몸통에 조준하고 클릭을 유지한다. **치료 연습**을 체크하고 새 탐사를 시작하면 착륙대 왼쪽 위에 피해와 맹독을 받은 아군 허수아비가 배치된다. 허수아비 가까이에서 `E`를 누르면 상태를 다시 설정한다. [회복·감속과 상태이상](startrail-crew-balance.md#상태이상)
- 무기마다 조준점, 명중 방향의 산포, 총구 불빛과 반동이 다르다. 스프라이트와 투사체는 같은 총구 좌표를 사용한다. 화면 위쪽을 조준하면 총구가 작아지고, 화면 아래쪽을 조준하면 총구가 커진다. 지도·퍼즐·HUD에서는 조준점 대신 엔진이 그린 포인터가 나타난다.
- 무장한 대원은 조준 방향에 맞는 소매 자세를 쓴다. 두 손을 소맷부리에서 현재 무기의 손잡이와 받쳐 드는 위치에 연결하고, 반동과 재장전 중에도 투사체와 같은 무기 좌표를 사용한다.
- `WASD` 또는 방향키를 누른 채 `Space`를 누르면 입력한 방향으로 구른다. 두 방향을 동시에 누르면 대각선으로 이동한다. 벽이나 장애물이 길을 막으면 일찍 감속하고 일어서며, 회피 동작 중에도 피해를 입을 수 있다. 꼬미는 솔오리보다 조금 더 멀리 구른다. 조작 중인 대원의 체력이 바뀌면 발밑에 체력바가 1초간 나타난다.
- 보급 상자와 얼음 결정을 공격해 파괴할 수 있다. 파괴된 물체는 잔해를 남기며 물리 충돌과 빛 가림에서 빠진다. 중계소와 승강기는 임무 시설로 유지한다.
- 서쪽 탐사 구역과 남동쪽 창고의 보급품은 `E`로 한 번 받을 수 있다. 체력, 장비에 장착한 탄창과 예비 탄창, 드론 배터리 및 조명탄을 최대치까지 채운다.
- 손전등은 중앙에서 가장 밝다. 바라보는 방향에서 벗어난 영역은 플레이어와의 거리가 멀수록 점차 어두워진다. 총구 섬광은 기본 조명 합성 뒤에 가산하여 손전등과 겹치는 부분을 더 밝힌다. 가까이에서 사용할 수 있는 발전기와 무기는 노란 윤곽과 옅은 노란색으로 표시한다. 조명의 거리와 밝기는 밸런스 테이블에서 관리한다. [1-1 적용값](startrail-crew-balance.md#1-1-적용값)
- `Tab`으로 상세 지도, 지형과 표식을 20% 불투명도로 보이는 오버레이, 지도 닫기를 순환한다. 확인한 벽은 밝은 실선, 닫힌 차단문은 붉은 점선으로 남는다. 미탐험 지역은 비어 있다. 오버레이의 플레이어 표식은 화면 속 캐릭터의 발 위치와 일치한다. 오버레이를 켠 상태에서도 이동과 사격이 가능하다.
- **픽셀 크기**는 1~5픽셀 중 선택한다. 기본값은 2픽셀이며 1픽셀에서는 원본 해상도로 표시한다. **웹뷰 해상도**와 **전체 화면**으로 표시 크기를 바꿀 수 있다.

### 회로 퍼즐과 전투 보조

미니게임은 엔진에서 상호작용 입력과 성공 조건을 제공하고, 해당 시설은 완료 이벤트로 상태를 전환한다. 발전기는 4×4 회로 그림에서 무작위로 여덟 조각을 먼저 배치한다. 오른쪽 조각을 드래그해 빈칸을 채운다. `Esc` 또는 닫기 버튼으로 나왔다가 배치를 이어갈 수 있다. 퍼즐을 푸는 동안 적과 특수장비가 계속 움직이고 플레이어도 피해를 받는다.

| 조작 | 장비와 용도 |
| --- | --- |
| `1` → `Q` | 배치 미리보기와 진행 막대가 표시된 상태로 `Q`를 3초간 눌러 포탑 한 대를 설치한다. 설치 중에는 제자리에서 사격·나이프 공격·재장전이 가능하며 이동과 구르기는 잠긴다. 대기 중 총구는 시계 방향으로 회전하며 좁은 손전등을 비춘다. 가까이서 `E`를 1초간 눌러 회수한다. |
| `2` → `Q` | 드론 한 대가 본체 아래에 좁은 조명을 비추며 따라다니고, 가까운 적을 추격해 사격한다. `Q`로 호출·회수를 전환한다. 방전되면 자동으로 회수되며, 배터리가 조금이라도 충전되면 다시 호출할 수 있다. |
| `3` → `Q` | 포인터를 향해 조명 수류탄을 던진다. 날아가는 중에도 주변을 밝히며, 착지하면 바닥을 구르고 캐릭터와 몬스터에 밀릴 수 있다. |

포탑과 드론은 시동음에 이어 활성 신호와 구동음을 내고, 표적을 발견하면 붉은 광선으로 전방 지형을 약 0.48초간 밝힌다. 적은 탐사대원을 우선하되 장비를 공격해 파괴할 수 있다. 대원의 체력이 32% 이하면 화면 가장자리가 붉게 맥동한다. 테스트 페이지의 **볼륨**은 배경음과 효과음 전체의 크기를 조절한다.

### 1-1 적 구성

| 적 | 교전 방식 |
| --- | --- |
| 얼음 진드기 | 좁은 길에서 추격해 접촉으로 공격한다. |
| 빙하 멧돼지 | 앞쪽에 돌진 예고가 보이면 직선으로 돌격한다. |
| 균열 정찰병 | 조준선을 예고하고 에너지탄 한 발을 쏜다. 가까이 다가가면 거리를 벌린다. |
| 중장 경비병 | 긴 예고 뒤 세 방향으로 에너지탄을 발사한다. |
| 서리 포자 | 부풀면서 둥근 범위를 예고한 뒤 냉기 파동을 일으킨다. |
| 빙각 굴착충 | 몸을 낮춘 뒤 짧고 빠르게 돌진한다. |

여섯 종 모두 방향별 실루엣의 크기를 맞추고, 죽으면 쓰러지는 전용 자세를 쓴다. 쓰러진 뒤 충돌과 공격 판정에서 빠지고, 바닥 그림자와 함께 서서히 사라진다.

### 환경과 캐릭터 아틀라스

내장 ImageGen으로 원본을 만들고, 각 프레임을 아틀라스에 정렬했다. 런타임의 픽셀 렌더러가 최종 출력 크기를 결정한다.

### 음악과 효과음

고전 공포 게임을 참고해 CC0 음악 원본에 바람, 금속, 잔향을 섞고 네 곡을 스테레오 루프로 편집했다. 스테이지에 진입하거나 다시 탐사할 때 한 곡을 무작위로 고른다. 브라우저에서 첫 입력이 들어오면 재생하고 음소거 버튼으로 음악과 효과음을 끌 수 있다. 포탑의 구동음·감지음과 드론의 전기 모터음은 거리에 따라 작아지며 장비 효과음은 30% 낮춘 음량 배율을 사용한다.

## 첫 검증 범위와 플랫폼 연결

친구 방 검증은 PC 브라우저에서 실제 두 사람이 플레이하며 진행한다. 첫 임무의 맵 두 개, 조작 가능한 캐릭터 두 명, 나이프와 기본 총기, 작은 무리형·큰 돌진형을 우선 사용한다. 공개 목표는 최대 4인 협동이다. 추가 행성, 3~4인 밸런스와 모바일 가로 화면 조작은 후속 검증 범위다.

- **엔진과 플랫폼.** 모든 플레이 기능과 게임 로직은 Phaser 게임 모듈이 담당한다. 입력·물리·전투·AI·장비·스테이지·조명·HUD·미니맵과 게임 결과 판정도 여기에 포함된다. React 웹단은 라이브러리·대기실·게임 마운트·공통 결과 화면을 담당하고, 게임에서 내보낸 확정 결과를 표시한다. 선택된 게임의 Scene과 리소스만 로드한다.
- **온라인 판정.** 기존 친구 방의 WebRTC 직접 연결을 우선한다. 각 브라우저는 조작에 즉시 반응하고, 호스트 엔진의 물리 월드가 충돌·밀림·명중·AI·임무 진행의 최종 상태를 정한다. 위치와 속도, 현재 스테이지와 서브미션 상태를 필요한 주기로 동기화한다.
- **복구와 비용.** 공통 연결 대기·중계 전환 흐름을 재사용한다. 재접속 시 호스트가 확정한 맵과 동적 물체, 적, 시설, 구조 진행을 복원한 뒤 이어서 플레이한다. P2P와 중계에서 입력 지연, 오차 보정과 트래픽을 비교해 갱신 빈도를 정한다. 검증은 기존 인프라와 무료 이용 한도 안에서 진행한다. [놀이버스 기술 검토](technical-design.md)

## 개발 착수 시 확인할 기준

| 검증 | 처음 확인할 동작 |
| --- | --- |
| 조작과 물리 | 이동하면서 독립 조준하고 공격한다. 같은 타격에 질량별로 밀림이 달라지고, 플레이어와 괴물이 서로 밀려 이동한다. 벽 근처와 좁은 통로에서도 충돌이 유지된다. |
| 조명과 시인성 | 마우스를 돌리면 캐릭터와 손전등이 함께 돌아간다. 벽 뒤는 어둡고 움직이는 대상의 그림자가 따라간다. 어두운 구간에서도 길과 돌진 예고를 구별하고 미니맵에서 팀원 위치를 확인한다. |
| 협동의 필요성 | 실제 두 사람이 한 명은 패널을 조작하고 한 명은 방어하는 행동을 자연스럽게 선택한다. 역할을 바꿔도 진행할 수 있다. |
| 지도와 스테이지 전환 | 초보 두 사람이 방향 안내를 끈 상태에서 배경을 보고 길을 찾고, 서브미션을 클리어해 종료 지점에 도달한다. 1-1의 승강기에서 1-2의 새 지도로 이어지는 맥락을 알아볼 수 있다. |
| 혼자하기 | 같은 경로에서 복구와 방어를 번갈아 수행해 완주할 수 있다. |
| 온라인 복구 | 전투·시설 복구·스테이지 전환 중 참가자 연결을 끊고 다시 연결했을 때 양쪽의 맵, 물체 위치, 진행 상태가 일치한다. 직접 연결과 중계에서 같은 판정이 유지되는지 확인한다. |

개발 전에 장비 교체와 특수장비의 입력, 스테이지 사이에 이어지는 체력·탄약 상태, 외계인 첫 등장 구간을 확정한다. 개발에 들어가면 좁은 통로 한 곳에서 먼저 이동·밀림·손전등과 돌진 예고를 함께 검증하고, 이어서 중계소 복구와 스테이지 전환을 확인한다.
